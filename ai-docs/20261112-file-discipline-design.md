# 文件纪律：文件上怎么写就怎么读（设计）

> created 2026-11-12 by Claude Fable 5.2（MoonSinger 统筹）· as-of v0.17.11（dev）/ 2026-11-12
> user 2026-11-12 夜（「换上新读法」上了开发版之后）：「看来我们的文件纪律还是有价值的，可以记一个设计文件」。
>
> **这一份是什么**：歌的文件格式现在按什么模型读和写。第一次碰 `src/format/` 的人读这一份，就知道该怎么写、哪些路别走。
> **这一份不是什么**：规矩和 user 的原话在两份 `CLAUDE.md` 里（家族根「文件就是语义：严禁静默转换」，本仓「文件就是语义：本仓的细则」）；那一晚的经过在纪要 `talks/20261111-two-display-modes-meta.md` 第 135–137 节；施工的账在施工单第 14–16 条。这一份和它们冲突时，以 `CLAUDE.md` 和 user 后来说的为准。
> 下面除了标成引用的句子，都是统筹的归纳，user 没逐字说。

## 一、一句话

歌的文件要活得比程序久。程序读它的时候，当作以前的版本不存在：文件上写着什么就是什么。

- user：「相当于之前的版本全都不存在，我们只有这么一个文件格式，你文件格式怎么样就怎么样读。」
- 判据分两层。
  - **底线**：文件里的数就是它写的意思。程序没了，光看文件就知道这个东西是多少。user：「如果我们这个程序没了，你通过文件的语义能知道这个东西有多小，而不是说你要复现的话，你必须要得到我们这个程序的源代码去看里面那有一个减六，这个是我无法接受的。」
  - **理想**：只有文件、没有程序，能把声音复现出来。做得到多少算多少。

## 二、模型：四个动作

| 动作 | 做什么 | 不做什么 |
|---|---|---|
| 打开 | 读现行格式里有定义的键；缺的数用模板补 | 不改文件；不往谱里加东西；不问这是哪一版写的；不猜 |
| 保存 | 把眼前这一份按现行格式写出去，每个键都明写（等于默认也写） | 不写现行格式没有定义的键 |
| 新建 | 把模板里的数按值抄进文件 | 不留「没写 = 某个数」 |
| 调默认值 | 改模板，只影响以后新建的歌 | 不动已有的歌 |

user 给的模型：「就相当于这是两个不同的软件，然后你转码」「你保存新了的话，你看到的就是你现在看到的那一份」。

出声的代码只吃明写的数，自己不带默认。这是理想，不极端：算法内部的结构数（平滑、淡入淡出）跟算法走；进文件的是有物理意义、人可能想调的数。user：「我们的引擎里没有常数量。…当然也不用那么极端，我说的是理想情况。」

## 三、保证什么，不保证什么

- **保证：谱。** 每张纸、每个声部的音、歌词、记号，读出来逐个相同。这是红线，任何一步有一首不同就停。user：「我们真正保证不会发生改变的是这个谱子」。
- **不保证：声音和版面在各个版本里一样。** 算法改对了，老歌跟着变。老歌里写着的数程序不替人改，由人自己调。user：「我是比较倾向于老歌我自己调」。
- **不许：为了和以前一样而加任何东西。** 常数、分支、换算、对照表、开关，目的是复现以前的行为的，一律不进。user：「我最怕的是你换了算法之后，你为了让它和之前看上去一样，你加了一个减六，这个是我绝对没法容忍的。」「我真的没法接受这些 if else」。

## 四、读不懂的时候：每一种有一个出口

规矩是两句：单纯的数缺了，用模板补；指向别的东西的地方读不到，显示成断的，不拿默认的顶上。user：「顶多是引用断了，你重新连一下不就行了？…你断了之后，你看到了，你重新连。但如果静默改了的话，你都不知道变成啥了」。

| 读到什么 | 程序怎么办 | 人在哪里看到 |
|---|---|---|
| 一个数没写 | 用模板的值；存的时候写下来 | 不说 |
| 现行格式没有定义的键（退役的、别的软件写的） | 读的时候不理；存的时候不写 | 不说 |
| 这个声部的乐手读不到 | 没人上场，不出声；存的时候不替它造一位 | 「不出声」清单，分三种原因；声部名写「（没有乐手）」 |
| 合租的主人不在 | 照没有合租来画；存的时候照原样写回 | 歌手牌「合租」那一行 |
| 发送 / 出到的混音轨不在，被谁压的那条轨不在 | 那一条不接 | 那一格红字；卡片上一行「有 N 处断了」 |
| 录音房那一份在，但读不出现行格式的轨表 | 各轨用模板；总轨照文件 | 打开时一句话（v0.17.11 还没有，已排） |
| 谱的扩展读不懂 | 不打开 | 明说读不懂 |
| 别家的谱没写速度 / 调号 / 拍号 | 用默认开 | 打开时各说一句 |
| 视图态读不懂 | 用默认 | 不说（它不是内容） |
| 比这一版程序新的文件 | 大版本新 = 不开；小版本新 = 能开能存，不认识的键原样带回 | 不开时明说；能开时说一次 |

## 五、版本记号还剩什么用

程序里看版本记号的地方只有一处：这一份比不比自己新。它在读写的门口。

- 没有「如果是某一版之前的」。
- 存的时候判「现行没定义的不写」也只用这一处：这一份不比自己新 = 只写有定义的键；比自己新 = 不认识的原样带回，那是新版本的东西，旧程序不毁它。
- 程序里不留老键的名字，也不留退役键的名单。退役一个键，不用给程序加一行。
- 文件里记着是哪一版程序存的。那是给人看的，程序不拿它分路。

user：「猜老歌是什么意思？猜老歌是什么版本？这个是我最没法接受的」。

## 六、格式怎么往前走

- **只加不改。**
- **一个键的意思永远不变。** 想换意思，就换一个新名字的键。user：「键必须要和语义对齐」。
- **「没写」不许有意思。** 不许用有没有某个键来表示一种状态；「跟着谁」「是不是自动」都明写。
- **退役 = 现行格式不再定义它。** 没有升级的步骤。
- **没有升级链。** user：「我最讨厌的就是说，我这个一辈子每多一次改动都会多一轮这个转换，最后一个长长的转换算法，这个我是真的非常讨厌。所以说尽量就说文件上怎么写我们就怎么弄，可以吧？就相当于我们文件是永生的。」
- **转换只有一种情况允许**：不转换就整个读不了。那时必须弹对话框，逐条说明白了才做。user：「如果是必须要的话，才谈对话框。就是说，如果不转换，你整个算法都读不了的时候才是。」（谈 = 弹，语音。）到 v0.17.11 为止一次也没有用到。

## 七、默认值和「用默认」

- 默认值住在「新文件的模板」里。模板和歌是同一种格式的数据。
- 「用默认」有两种，必须明写是哪一种。
  - 跟着的东西被文件钉住（按内容哈希引用的音色库、嵌在歌里的东西）或者是公开的标准 = 可以存「跟着它」。
  - 跟着的是软件的默认 = 人点「默认」的那一刻，把这一版的值抄进文件，之后它就是一个数。
- 每位乐手按值带着自己的力度表。
- **代价**（user 认了）：软件以后有了进步，老歌不会自己跟着变。user：「带公式、带数字，唯一的问题就是我们到时候有一些新的进步之后，老歌得手动调。我觉得这个反而是一个比较好的权衡」。
- 接这个代价的办法：乐手设定里和现行默认不一样的行标出来，旁边一颗「默认」。不在打开时提示，不做专门的页面，不自动替人换。
- 响度够不够、该是多少，由 user 的耳朵定。AI 量的数只进表，不提议影响响度的默认值。
- 归一化只在没有作者意图的地方定（小月相的那一个倍数，写进文件、露出来能调）。音色库里各件乐器之间的轻重是库作者调的，不碰。

## 八、走过又退回来的路

这几条都是那一晚真的提过、被 user 否掉或者自己发现错了的。以后别再提。

1. **用第二个数去抵消第一个。** 乐手带着 −6，就在总轨加 6。问「要不要加一个数去补」之前，先查是哪个数造成要补，能拿掉源头就拿掉。
2. **开文件时替人换算。** 老歌打开时每位乐手一律加 6。写在文件里、界面上看得见的数，软件不替人改。
3. **升级链，每一步配一个对话框。** 没有转换，也就不要对话框。
4. **退役的键原样带回。** user 倾向于删：存了之后，文件里就是眼前这一份。
5. **猜。** 按年代、版本、有没有某个键，推断老文件里的东西是什么意思（比如老歌的声部名是人起的还是软件抄的）。现在照文件显示，人嫌烦自己改。
6. **把数从文件挪进程序。** 把小月相的力度做成程序里的公式、删掉文件里的表。方向反了，要改回成文件里的表。
7. **按物理量把各件乐器拉齐。** 会把别人调好的东西调乱。
8. **读不到就拿默认的顶上。** 乐手读不到当成小月相。
9. **拿「老歌逐样本不变」当验收。** 纯整理代码的除外。
10. **为旧版本的程序加东西。** 给旧版本照写旧键、拿旧版本的真代码实测一轮。记忆里记着 user 2026-11-13 在三维那边的话：「这个是为了减负的不是为了增负的，关键是舍去历史包袱，专心做prealpha。我们现在是prealpha」（这句是别的会话记下的，这里没有回对话记录核过）。

## 九、验收怎么写

- 交付写「变了什么」：哪些歌、几处、人会看到或听到什么。
- 谱的 token 串逐个相同是唯一的红线。
- 底本红了只有两条出路：是毛病就修；是有意的改动就重冻，并写明变了什么。
- 拿 user 的歌库核对时只读、只报数，不报歌名，脚本和结果不进仓。
