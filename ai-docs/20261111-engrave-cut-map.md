## 二、搅在一起的地方：跨段读写的局部变量，打算怎么拆

按难度排。行号同上。

- **A. 两段坐标（最难）。** `rowTop / rowAbove` 在第 900 行先设成临时高度，所有「画」都在临时高度上用 `yOf` 画；第 1701 行再改成最终位置，第 1709–1710 行按 `round(y / 8192)` 认出每个图元、每个点击框属于哪一行再整行挪。所以 `yOf` 在第 6 步里是临时坐标，在交出去的 `Layout` 里是最终坐标，同一个闭包两个意思；「属于哪一行」藏在 y 值里。
  - 拆法：画法在**行内的局部坐标**里画（原点 = 这一行自己的基准，五线谱 = 第五线），按行交回图元和点击框（明着的「每行一张表」）；框架记每行的上下天际线、定位、整体平移。`round(y / 8192)` 这个认行的办法退场。`yOf / dOf` 变成「行数据 + 几何纯函数」（第三节）。
- **B. 单元对象被就地改。** 第 792 行「量」的时候顺手写 `u.inkL`；第 861 行「摆」把 `x / system / w` 写回每个单元；后面「画」和光标落点全读单元上的这几个值。
  - 拆法：「量」交回的列自带「往左占多宽」（就是 `inkL`）；「摆」的结果单独一张表（第几列 → 横坐标、第几行、列宽），画法从这张表读，单元不再被改。
- **C. `keyNow` 被临时换掉再换回来。** 第 807 行 `headAt` 为了算「从第 k 列开一行，行首多宽」，把共享的 `keyNow` 清空、填成第 k 列之前的调号、算完再填回去；第 843 行最后又整体改一遍。
  - 拆法：五线谱的「行首多宽」直接吃「这一刻每个声部的调号」（`keyAtCol[k]` 本来就算好了），不碰共享表。这正好是设计稿的 `lineStart(track, tick)`。
- **D. 挂件队列 `later[13]`。** 第 5、6 步各个声部把闭包排进去（闭包抓着这个声部的 `dynItems / lyricJobs / partLyrics / artEdge / stemXOf / tipOf…`），第 1675 行按「第几样、再按登记先后」统一执行。天际线是每行一条，所以不同行之间的先后不影响结果；同一行里会有两个声部的（声部 2 画在声部 1 那一行），这时先后要保持。
  - 拆法：框架持有「挂件表」（第几样 → 一串），画法往里登记（带行号）；执行顺序照旧「先按第几样、再按登记先后」，登记先后照旧按声部顺序。这样图元的先后逐个不变（守卫 3 要求连先后都相同）。
- **E. `right / sheetRight / sysStarts / staffEnd`。** 由「排」算出，被「画」的很多地方读：连音线 / 连线 / 渐强渐弱跨行时的开口端（`P(right)`、`sysStarts[b.system]`）、整小节休止的左右边、房子画到哪、渐强渐弱每行从哪起（`leftOf`）。
  - 拆法：框架交给画法的「这条轨在这张纸上所有行的位置」里带上每行的起点（行首之后）、五线画到哪、右边界。
- **F. 歌词。** 按节奏排（第 884 行）要每个字的中心（`u.x + 0.6` = 五线符头的偏移）；贴天际线（第 1579 行）要「挂在哪一行」（大谱表下面那条）；`lyricsOf / lyricOff / lyrPlan / lyricJobs / partLyrics` 横跨第 4½、6、12 步。
  - 拆法：歌词整段归框架；画法交「每个音的歌词锚点横坐标」和「歌词挂在哪一行」。
- **G. 合租那一组表**（`absorbed / virt / lowOf / voice2Of / shareWith / startFor / drumNames / openFams / loIds`，第 601–657 行）被每个声部的单元、`posD`、`stemInput`、第 5b 步的名字全读。
  - 拆法：谱种的表（五线）一次算好，交出「这张纸排哪几行、每行吃哪几条轨（含声部 2、双手谱下面那张）、开头谱号、鼓的名字顺序」；框架只按这份清单排名字和括号。叠成一行的那一家是五线谱的规矩（简谱各占一行），留在五线谱那边。
- **H. 家具的竖向位置钉在五线上。** 名字竖着居中用中线（`MID_LINE`），点击区、色条、左边竖线、合租括号用第一线和第五线（`TOP_LINE / BOTTOM_LINE`）。
  - 拆法：画法给每行三个竖向锚点（上沿、中线、下沿；五线谱就是这三根线），框架只读锚点，不认识第几线。
- **I. 每行的上下留白。** 第 1684 行最小值用「+4」（五线的高）、大谱表上面那条用 `graveUpper`、没歌词的用 `rowHNoLyric`。
  - 拆法：画法报这一行自己的高和最小上下留白，框架只取大、按整格往上取、叠。
- **J. 速度归谁画、上一段结尾的速度**（`owner / prevBpm`）：框架算（只看时间和声部顺序），交给那一行的画法。
- **K. 界面语言**：见〇-4，语言作为输入。
- 留在框架里、不用拆的：`yCur / pageNo / ensure`、各张输出的点击表、`shortBars`、`drawn`、测试钩子 `__noAnn`、天际线的临时数组 `pieces`。

「通用」= 和谱种无关；「五线」= 五线谱专属；「混」= 形状通用但值或名字带五线的意思。

|---|---|---|
| `prims` | 通用 | 图元本身不认谱种；内容由画法决定 |

## 八、「量 → 排 → 画」套在五线谱现在的排法上，哪里套不上

1. **「量」要先排一遍符杠。** 符尾往右伸多远决定顶杆，而连不连杠要先按拍分组（第 769–771 行用「不折行」假设排了一遍）。放进「量」里可以，但「量」就不是只看单个音：它看整条轨的分组。现在一拍里折行只在一个小节一行都放不下时才有，这个近似已经接受了。
2. **列的「第几个」和「先后」是共享的词。** 合成列的键是（时刻、先后表 `SLOT`、同种第 n 个）；`SLOT` 写着小节线 0、房子 0.5、谱号 0.8、调号 1、拍号 2、速度 3 … 音 5。简谱的行和鼓的 X 行（同一张纸上不同画法的行）要对齐，就得用同一张先后表。这张表要从五线谱里拿出来，归框架。
3. **横向还有三处五线谱自己的规矩不在列里**：整小节休止不参加间距、画在两根小节线正中（第 1152–1160 行，找左右小节线）；行末小节线之后五线不出头（`staffEnd`）；行首宽里第一行多一个拍号。都能表达，但「画」要拿到小节线的横坐标和行的右界（拆法 E）。
4. **「画」不是逐行的**：跨行的连音线 / 连线 / 渐强渐弱 / 八度线 / 连音括号 / 房子（〇-2）。
5. **「画」和「叠」交织**：现在先画音符层、量墨、再按「第几样」把挂件一样一样贴上去（贴一样天际线长一点），最后才定行距。设计稿的「画 → 交回这一行上下各占多高」是一步；实际是「画音符层 → 框架贴挂件 → 才知道多高」。所以画法要分两次交：音符层的图元 + 一张挂件清单（第几样、贴哪一行、上还是下、离多远、画什么），由框架贴。拆法 D 就是这个。
6. **挂件里一半是谱种无关的**：力度字、渐强渐弱、渐到、反复房子 / 跳转、速度、风格、小节号、歌词——简谱都要，逻辑一样，只是横坐标的锚点不同（五线 = 符头 x + 0.35）、字形可能不同。框架不许认字形，所以它们不能进框架。我的打算：1b 先留在五线谱这一边、但收成「吃锚点横坐标和行」的函数；第四刀简谱真要用时再抽成两种画法共用的模块（第二个用户出现时再抽）。**统筹要是想 1b 就抽出来，说一声。**
7. **一条轨不一定是一行**：大谱表一条轨占两行，声部 2 一条轨占 0 行（画在声部 1 那一行），合租几条轨并成一行，双手谱一家并成两行。设计稿的 `RowSpec { kind, tracks[] }` 盖得住，但「点击区属于哪一行」现在用的是 `SystemBox` 的下标（一张谱表一个），1b 照旧一张谱表一个 `SystemBox`，点击的地址不变。
8. **守卫 6 有两个天然例外**：一条轨变长 / 变短，别的声部后面补齐的空小节跟着变；合租一家里任何一位改了，叠出来的虚拟轨跟着变。见〇-3。
