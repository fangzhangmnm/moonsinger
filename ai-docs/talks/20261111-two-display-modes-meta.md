## 1. AI：「只有我们看得懂」有两层原因

- **不认得符号**（北约符号的问题）：不读五线谱的人不认识跳音点、重音、× 符头。
- **认得也会读错**（方言的问题）：我们给记号的意思不是标准意思，而且跟着演奏者变——同一个跳音点，钢琴上 = 截短，小月相上 = 下一个字前顿一下；× 符头 = 气声；重音对小月相 = 顿一下再加响；音内渐强 / 渐弱 / 鼓起在 MusicXML 里根本没有，存在我们自己的文件里。读五线谱的老手看到也会按标准意思理解。
- 「画坦克」那种模式两层都能解决：不画记号，画「这位歌手实际会怎么演」。

## 2. AI：三层分开——记号 / 意思 / 画法

- **记号**（文件里写的）：照旧，**文件格式不动**。
- **意思**（这位演奏者拿它干什么）：已经有了，就是乐器页里「记号怎么演」那张表（每位演奏者认哪些记号、各自参数；不认的画灰）。这一层相当于红龙里单位本身的数据。
- **画法**：「记号」模式 = 画记号本身（现在的样子）；「画出来」模式 = 按这位演奏者的意思画效果。
- 推论（AI）：「画出来」模式是**跟着歌手走的**——同一个跳音点在钢琴那行画「短」，在小月相那行画「顿一下」。
- 推论（AI）：放弃的曲线以「只看、不写」的身份回来——写还是用记号（快），「画出来」模式把记号翻译成形状给人看（音量起伏画成音条变粗变细、顿一下画成音前一道小缝、气声画成空心或虚线的音……具体画法是设计稿的活，这里只是举例）。

## 3. AI：显示方式是两根互不相干的轴

- 轴一 **用什么谱**：五线谱 / 简谱 / 字母简谱 /（以后）钢琴格 / tracker。
- 轴二 **记号怎么显示**：记号 / 画出来。
- 两根轴分开，「画出来」只设计一次，每种谱都能用；不然每种谱各自发明一遍挪用记号怎么显示。
- 例子（AI）：会读简谱的长辈 = 简谱 + 记号（简谱自己就有一套标准记号：跳音 ▼、重音 >、换气 V、念白用 X 代替数字——**AI 凭印象，没核出处**）；小孩 / 新手 = 简谱 + 画出来；按字母想音的朋友 = 字母简谱 + 画出来；我们自己 = 五线谱 + 记号。
- 键盘的符号层要跟着同一个开关：谱上显示「顿一下」，符号键上也要显示「顿一下」，不然看的和按的对不上。输入照旧写记号；同一位歌手两个记号演出来一样（比如小月相的跳音和重音都会顿）时怎么区分，是设计稿要解决的一处。

## 4. AI：设计稿要覆盖的量（现状清单，v0.16.107 代码里数的）

- 挂在音上的演奏法 16 种：跳音、重音、强音、突强、强后即弱、保持、呼吸、次重音、弱化、幽灵音、气声（× 符头）、音内渐强 / 渐弱 / 鼓起、琶音、滚奏。
- 另有：连线、力度 ppp–fff、渐强 / 渐弱、渐到、风格记号（拍子轻重）、句号、小月相的吸气、速度、调号、拍号。
- 演奏者三类，各认一部分：小月相（认气声、吸气，不认保持 / 连线 / 琶音 / 滚奏）、元音版、SoundFont 乐器（不认气声）。
- 现成可借：剪贴板已经有一种简谱文字写法（`1_ 2_ | 5 - -`、叠音 `1&3&5`、句号 `,`、渐强 `[<]`）；pad 键上已经画简谱数字 + 八度点。

## 10. 权衡取舍（user 11-11「不不不现在还没拍，我们要做好权衡取舍」）

AI 的整理，user 没拍：

- 每往下一档 得到 / 付出：
  - 简谱（七岁上下 + 长辈）：得到 = 兑现 itch 上的 coming soon、补上「唯一歧视不会五线谱的人」、音乐课本来教简谱、长辈；付出 = 一个全新的排版器（数字 / 下划线 / 八度点 / 多声部怎么叠），最大的一块工；以后每个新记号都要在简谱里再设计一遍。
  - 数字 + 颜色 + 形状（三到五岁）：得到 = 不识字也能自己写，小月相把按的唱出来（玩具琴做不到）；付出 = 见下面的结构冲突。
  - 只剩先后顺序（两三岁）：节奏只能从按的时机来（实时按、app 对拍子）；小孩按不齐 → 对出来的谱乱，他自己又改不了。
- 结构冲突（比岁数要紧）：
  1. 颜色这条通道已有主人：乐器类别色、灰 = 做不到 / 唱不出来（「画灰 + 明说」纪律）、蓝光标、橙播放。音按级数上彩虹色 → 灰不再显眼，诚实那条纪律被稀释。
  2. 「明说」靠读字：不识字的人看不懂为什么灰、冲突三选一、锁。数据安全红线不能降级 → 越往下，存档 / 同步 / 冲突越要整块交给大人，写的那一面和管文件那一面要分得开。
  3. 尊老和爱幼在颜色上分叉：长辈要大字和简谱，未必要彩虹（可能嫌幼稚）→「用什么谱」「字多大」「叠不叠颜色形状」是三个各自的开关，不能捆成一个「儿童模式」。
  4. 功能 × 画法是乘法：每多一种画法，以后每个新记号都要多设计一遍。不想变乘法 → 先有「记号 → 意思 → 图」那一张表当唯一来源，加一个记号只加一行。
  5. 越往下，拿记号管情绪这个本事越用不上；孩子那一面基本只剩「小月相把你按的唱出来」。
- AI 的推荐（等 user 定）：下限按判据定，不按岁数。候选 A 一个人自己能用到底（含存文件、处理冲突，约七八岁）/ B 自己能当作者、文件归大人（颜色形状那一档）/ C 能玩出声就行。推荐 B 当设计的地板（缝按它切：三个开关分开、一张意思表、写和管文件分开），施工先只做 A 那一截（简谱 + 大字）。

## 20. 真正拦路的：意图（记号）↔ 数（每个音的元数据）不可逆（user 11-11）

- user（引 AI「粗细…用在每个音自己的强度阶梯上…」）：「我一开始想的也很好，但是后来发现其实关键，这个和piano roll, tracker会打架，就是我们现在曲线是abuse music notation。但是到了这边的话反而是一个一个token的元数据，所以两种模式也许没法lossless转。其实可能真正拦住我们的只有这一点？」
- AI（没拍）：
  - 分两家：**token 一家**（五线谱 / 简谱 / 字母）之间是无损的（同一串 token 换画法；只差谱号 / 八度线这类只管画的 token）；**格子一家**（钢琴格 / tracker）和 token 之间是单向的：token → 格子是一个函数（算出来就是），格子 → token 不是。
  - 不可逆的有两处，根是同一个（我们存的是意图，格子存的是结果）：
    1. 表情：我们是记号 + 状态机（p 管到下一个力度、渐强渐弱 = 两个状态之间的过渡、风格记号按拍位加减），格子里是每个音一个数（力度）/ 一条自动化曲线。在格子里随手改一个音的力度 = token 里没有一个记号说得出这件事——要么加「每个音的力度覆盖」（= 把放弃的曲线请回来），要么把它吸到强度阶梯的几档上（有损、会猜）。
    2. 时间结构：钢琴格允许同一个声部里音互相重叠、和弦里各音长短不一、音随便放在哪个格上；我们一个声部是一串、和弦同长。格子里拖出来的这些，token 装不下。
  - 第三件陷阱（静默）：记号的意思跟着演奏者变（跳音在钢琴上 = 短、小月相上 = 顿一下）。格子要是画「实际出来的长短 / 力度」，换个乐器格子就自己变了，人什么都没动 = 静默；画「写的」就和 token 一致。
  - 推论：格子那一家做成 token 的另一张皮——能画、能改的只限 token 说得出来的（音高、这一声部里的先后和长短、选强度阶梯的哪一档、把力度记号 / 渐强渐弱的边界在一条台阶状的力度道上挪），不许自由画力度和重叠。这样来回是无损的，代价 = 钢琴格的老用户（教育轴）会觉得「这不是真钢琴格」，画不了自由的力度。
  - 对这一纪元：简谱在 token 一家里，**这一处不拦简谱**；拦的是以后的钢琴格 / tracker。
  - 粗细给强度阶梯这条不受影响：强度阶梯本来就是每个音的元数据，格子里也能一一对上（条的粗细 / 深浅）；打架的是力度记号那种跨音的状态。
- 状态：**没拍**。

- AI（没拍）：输入范式不用变——小键盘本来就是一台简谱输入器（Nokia 彩铃的血统）：音键 = 1–7、「0」= 休止、「—」= 拉长一份（= 简谱的横线）、「/2」= 减半（= 加一道下划线）、/2 开着按「—」= 附点（= 简谱的「·」）。打「5 — —」在键盘上就是按 5、—、—。数据、命令、按键一个都不用动，互相转换和数据契约不受伤。
- 要规定的只是简谱画面上那几个「看起来是东西、其实是画法」的字形点了 / 删了算什么。AI 推荐：**一套命令、各种谱同一个意思**，简谱独有的字形只映射到已有的命令上：
  - 点横线 / 点下划线 = 选中它所属的那个音（下划线 = 那一拍的那一组）；选中一个音之后「—」长一步、⌫ 短一步，本来就是这样（v0.10.5「只选了一个音 = 改这个音」）。
  - 光标只停在音和音之间（同五线谱），画在最后一根横线后面；⌫ 照旧是「这个音变成一样长的休止」——简谱里休止不用横线，二拍休止画成「0 0」。
  - 代价（肌肉记忆）：简谱老用户会以为光标在「5 — —」后面按 ⌫ = 吃掉一根横线；我们是整个音变成休止。同一个键在两种画面上意思不同 = 形状编码里最打架的那种（memory：手感相同功能不同的控件最易打架），所以宁可让简谱用户学一次，也不让同一个键分两种意思。没拍。
- 状态：**没拍**。
