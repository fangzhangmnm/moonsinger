## 修订 1（2026-10-10 晚，user 回提案）：插件随便插、路由轨自己开

> edited by Claude Opus 5.5 2026-10-10

user：「插件：可以随便插，比如混响也是，你可以做中间的路由轨。比如我可以放两个路由轨然后放混响。所以就类似fl的devick stack这种？而不是写死说哪里能放什么。用最general最自由的方式」

改成：
- **每条轨 = 一串插件格，什么插件都能放在任何轨的任何位置**（人声轨、乐器轨、路由轨、总轨一样）；不按「这类插件只能放总线」分。
- **路由轨（= 总线）用户自己开、开几条都行**；上面放什么插件自己定（混响、延迟、压缩……）。新歌**不预先开**提案 3 那两条「短 / 长空间」总线（那是写死的摆法，作废）。
- **任何轨都能发给任何路由轨**（推子后发送，每条发送一个量）；**路由轨也能再出到 / 发给别的路由轨**——现在的引擎做不到：总线一律直接进总轨（`studio.ts render()`），格式里的总线也没有自己的 `to` / `sends`。要补：总线有 `to` + `sends`，引擎按依赖顺序处理；接成环 = 界面上不让连（灰掉、说一句），读到成环的文件 = 断掉成环的那条、明说（不静默改数据：存回去时原样）。
- user 补：「有一个默认总线，就是歌手和输出都是builtin的，但是你可以加混音轨」= **内置的只有两样：每位歌手一条轨（歌手进来就有、跟着歌手走）+ 输出（总轨）**；默认的走法 = 歌手轨直接进输出。**混音轨（路由轨）全是用户加的**，加几条、叫什么、放什么插件、谁发给它、它出到哪都由用户定。
- 默认 EQ 格（提案 1「能换不能删」）是 user 自己的说法，照旧；它只是每条轨链上的第一格，不限制别的格。

## 现在有什么（刀 4，Fable，v0.9.9）

- 数学都在：`src/engine/fx.ts` 六种原语（EQ 双二阶 / 压缩器可侧链 / 延迟 / Freeverb 式混响 / 合唱 / 增益），每种一张参数表，零分配、确定性、音频线程和离线导出共用。
- 录音房的走法：每轨 出声 → 演奏者的链 → 通道链 → 推子 / 声像 → 总线或总轨（发送在推子之后）→ 总轨链 → 限幅。
- 格式：`studio.json` v2 的 `FxV2 = { id, kind, on?, params, key?, note? }`。**缺的**：每个插件自己的版本号和升级方法；`kind` 是原语名，不是「插件」（同一个 EQ 原语可以包成好几种 EQ 插件）。
- 界面：录音室只有推子 / 声像 / 静音 / 独奏 + 总轨；没有插件格子。

## 提案 1：插件的数据形状（studio.json 一格）

```ts
interface PluginSlotV3 {
  id: string;            // 这一格在链里的身份（唯一）
  plugin: string;        // 插件 id，如 "ms.eq.auto"（ms. = MoonSinger 自带；以后别家的另起前缀）
  ver: number;           // 写进去时这个插件参数的版本
  on?: boolean;          // false = 引擎跳过（noop）
  params: Record<string, number | string | boolean>;   // "auto" 之类的字也能存（比如低切 = 按乐器自动）
  key?: string;          // 侧链：被谁压（别的轨 id）
  slot?: "eq";           // 默认格：界面上「能换不能删」；引擎不看这个
  note?: string;
}
```

- **插件登记表在代码里**：`PLUGINS[id] = { name, ver, params, migrate: [v1→v2, v2→v3…], make(sr, params) }`；`make` 里用 `fx.ts` 的原语拼。
- **读进来**：认识、版本旧 = 在内存里一路升级（纯函数）；认识、版本比 app 新 = 当不认识；**不认识（sunset 了 / 别家的 / 更新的）= 数据原样留着、引擎跳过、界面画灰写「不认识的插件（数据还在）」**——以后插件回来了，同一份数据又能用（你说的「sunset了数据还在，以后不sunset了又能回来」）。
- **存回去**：认识的写当前版本；不认识的原样写回。
- **默认格**：每条轨开一个 `slot: "eq"`，能在几种 EQ 之间换，不能删；关掉（`on: false`）= 引擎跳过。这是界面的规矩，引擎只认 `on`。
- **格式要升**：`studio.json` 2 → 3（`kind` 改名 `plugin`、加 `ver`）+ 一条迁移（原语名 → 对应的 `ms.*` 插件、`ver: 1`）+ 冻结 v3 样本、旧样本不删（格式红线区的规矩）。现在的歌里链基本是空的，迁移几乎是空跑。

## 提案 2：最基础的几个插件（第一批）

按混音的顺序排：**平衡 → 摆位 → 频率 → 动态 → 空间**。前两步不是插件（每条轨自带推子和声像），插件从第三步开始。

| 插件 | 干什么 | 什么时候用 | 第一下怎么拧 |
|---|---|---|---|
| **EQ（默认格，几种可换）** | 改一条轨的「高低频比例」 | 两样东西糊在一起、某条轨太闷 / 太刺 | 先低切（切掉这条轨用不着的低频），再决定要不要挖一刀 |
| 　· 自动低切 + 厚 ↔ 亮（默认） | 低切自动放在这件乐器音域最低音再往下一点；一个「厚 ↔ 亮」倾斜旋钮 | 绝大多数情况 | 什么都不拧，先听；pad 糊就把它往「亮」拧一点 |
| 　· 三段 + 低切 | 低架 / 可扫中频 / 高架（小调音台那种） | 想细一点 | 中频扫到「打架」的那一段，往下挖 2–4 dB |
| 　· 两刀一扫 | 低切 + 高切 + 一个只能往下挖的中频 | 专治「糊」 | 低切、再挖一刀 |
| 　· 参量（以后） | 五段随便拖 + 曲线图 | 精修 | — |
| **压缩** | 把忽大忽小拉平；可选「被谁压」（侧链） | 一条轨有的字太冲、有的听不见；人声一出来让 pad 自己让一点 | 一个「压多少」旋钮；侧链：pad 被月读压 |
| **混响**（放在总线上） | 「房间」：让声音有距离、有空间 | 最后一步；铃要远、人声要近 | 每条轨一个「发送」旋钮：发得越多越远 |
| **延迟** | 回声（一声一声地重复） | 让旋律尾巴有余韵，比混响更清楚 | 发送少一点、反馈低一点 |
| **合唱 / 加倍** | 把一个声音变「宽」、像好几个人 | 齐唱、pad 想更铺 | 宽度小一点开始 |
| **增益** | 单纯调大调小（插件链中间的音量） | 前面的插件把音量改了要补回来 | — |
| 总轨：**限幅**（已有） | 最后一道保险，不让削波 | 一直开着 | 不用拧 |

**空间的建议**：默认两条共用的空间总线（短空间 = 小房间 / 板式，给人声；长空间 = 大厅，给铃和 pad），每条轨两个发送旋钮；回来那一路自带一个 EQ（切低频、收一点高频，免得漫进人声的气声那一段）。团子按你的思路 = 月读两个发送都 0（耳语、裸接线），铃长空间发得多，pad 看情况。

## 提案 3：表（动画）

- 每条轨一个峰值表，总轨也有；**换回旧的那种灵敏动画**（user「我还是喜欢旧的动画」）。
- 性能的规矩 = **看不见就不算**（user「动画就是窗口不显示的时候不计算渲染，节拍器也一样」）：录音室没开 / 切后台 = 音频线程不报、主线程不画；开着才算。节拍器现在就是这样（速度框收起 = 停；后台 = 浏览器不跑 rAF）。
- 「EQ 动画」（user 提的）：EQ 格子里画这条轨的频响曲线，放的时候叠一条实时的频谱——同样只在格子看得见时才算。
