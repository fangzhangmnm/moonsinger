# 月读「变甜了」查案：实时引擎前后，她的声音经过的路改了什么

> created 20261010 by Claude Opus 5.5 · as-of v0.9.38 / 2026-10-10
> 同一份在写歌实验室仓 `ai-docs/20261010-tsukuyomi-sweeter-investigation.md`（user「这个如果有调查的结果的话应该落盘留档，然后写歌实验室也落一份」）。

user 2026-10-10：「以及其实fable做了那一轮及时播放引擎之后，月读声音一下变甜美多了。不知道是我错觉还是确实一开始的placeholder混音比较差」

**纪律**：AI 不许拿测量下听感结论（家族 memory「AI 不许听」）。下面只有「代码改了什么」和量出来的数；甜不甜归 user 的耳朵。

## 对比的两头

- **旧** = v0.9.0（2bda0a9，实时引擎之前；正式版 prod 现在还是这条路的 v0.8.17）。
- **新** = v0.9.1 起的录音房（`src/engine/studio.ts`），到今天 v0.9.38。

## 逐段对照

| 段 | 旧（v0.9.0） | 新（v0.9.1 起） | 量出来的 |
|---|---|---|---|
| 唱法核心 + WORLD（`sing-core.mjs`、`vendor/world/`） | 同一份 | 期间改过几次，都说默认路径逐样本不变 | **核过：相同。** 把 v0.9.0 的核心和 WORLD 抽出来，和今天的用同一个 piper、同样两句（うさぎ、団子第一句，noise 0）唱，输出的 sha256 一样（a493686c62fd / d8893219605e） |
| 念缓存的存法（v0.9.11） | 没有 | WORLD 分析的谱包络 / 气声存成 bf16（命中、未命中都过同一次舍入） | 和不舍入比，信噪比约 **60 dB**（两句 59.7 / 59.5 dB） |
| 每一遍「念」的随机性 | piper 带噪声念（noiseScale 0.667、noiseW 0.5，`DEFAULT_OPT`），每次重唱是新的一遍；分段的缓存只在这次打开里 | 同样带噪声；但 v0.9.4 起「念」按歌词缓存、v0.9.15 起存进全局池（跨歌、重开 app 也在）= 同一句歌词以后一直用同一遍 | 不是音色处理的变化，是「听到的是哪一遍」从每次重开都换，变成一直是同一遍 |
| 响度 | 整条声部的各句叠起来，按整条的峰值归一到 0.89 | 每句原样 × 0.89 / 0.42（`SUNG_GAIN`） | 新比旧响 **+0.5 dB**（うさぎ，三句整首峰值 0.445）/ **+0.7 dB**（団子，四句 0.454） |
| 采样率 | 22050 → 44100 我们线性插值混音，整首做成一个 AudioBuffer，浏览器再转到设备的采样率（iPad 多半 48000） | 22050 → 设备采样率，录音房里线性插值一次 | 线性插值本身的高频衰减两边一样（按 22050 算：5 kHz −1.5 dB、10 kHz −6.3 dB）；旧的多一道浏览器转换，浏览器用什么插值没核（要是也是线性，10 kHz 再 −1.5 dB） |
| 句尾 | 每句末尾 30 ms 线性淡出 | 不淡出，用核心自己的收尾 | — |
| 表情曲线 | 播放前乘，4 ms 平滑 | 播放时乘，4 ms 平滑（`GAIN_TAU`） | 同 |
| 声像 | 等功率，正中 ×0.707 | 同 | 同 |
| 母线限幅 | 离线前瞻，起压 3 ms、放开 150 ms | 实时前瞻 9 ms，起压 3 ms、放开 150 ms | 参数相同；真起不起作用看那首歌有没有顶到天花板 |
| 月读的校准 | 新建默认 −6 dB（10-08 晚起，两边都是） | 同 | 同 |

## 能说的

- **唱出来的声音本身没变**：核心和 WORLD 逐样本相同；浏览器里多的 bf16 误差比信号低约 60 dB。
- **放出来那一段改了的**：响一点点（约 +0.6 dB）、少一道采样率转换、句尾不再硬淡出。
- **最大的「不一样」可能不在处理上**：以前每次重开都重新念一遍（随机），现在同一句歌词一直是同一遍。
- 这些里哪一条让人觉得甜，或者都不是，**AI 判断不了**。

## user 补充：「我反而觉得旧月读在多声部的时候响度都不稳定」

代码上对得上的两处（只是事实，不替耳朵下结论）：
1. **旧路整条按峰值归一**：月读整条的音量 = 0.89 ÷ 全曲最响的那一下。改一个字、或者重开后重念出新的一遍，只要最响的那个音节变了，整条就一起变响 / 变轻。量到的每句峰值在 0.29–0.45 之间（うさぎ 三句 0.29 / 0.36 / 0.45）——单这一项就能差约 **3.8 dB**（20·log10(0.45 / 0.29)）。新路每句固定增益，这一项没有了。
2. **母线限幅**：几个声部叠起来顶到天花板（0.98）时，限幅器把整条混音一起往下压（起压 3 ms、放开 150 ms），月读也跟着被压。新路照旧有，参数一样；只在顶到的时候起作用。

## 怎么自己听着比

- **同一首歌、同一台设备**：正式版（根目录，v0.8.17 = 旧路）和开发版（/dev/，新路）各放一遍。旧路每次开歌都会重念，可以多放两遍听听「每一遍不一样」有多大。
- 想单独听「一直是同一遍」这件事：开发版设置里「清空念缓存」后再放，就是新念的一遍。

## 方法（脚本没进仓，依赖检疫桶里的 piper 壳）

- 核心对比：`git show 2bda0a9:` 抽出 `src/singer/{sing-core,world-wrap,en-front}.mjs` + `vendor/world/world.{mjs,wasm}`，和今天的各跑一遍 `singCore`（同一个 piper-node `override` session，`noiseScale/noiseW = 0`），比 `r.y` 的 sha256 和信噪比；bf16 一路 = 今天的 WORLD 分析过 `speech-cache.ts` 的 `toBf16 / fromBf16` 再合成。
- 响度：Lab 的 うさぎ / 団子 乐谱按休止切句，逐句唱 raw，整首峰值 → 旧增益 0.89 / 峰值，新增益 0.89 / 0.42。
