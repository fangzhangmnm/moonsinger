## 一、这一轮做哪三件

1. **3/4、6/8 这类拍子下，长短旋钮上的大时值换成带附点的。** user 2026-11-12：「wishlist 键盘那一轮改，对应3/4 6/8的时候，那些大时值音符能不能相应的换成带附点的。估计有一堆设计决策」。
2. **超大的屏幕上键盘做成浮窗。** user 2026-11-12：「wishlist 超级大屏的时候medo真的很难看，能不能变成一个类似右下角浮窗的东西，键盘轮好好设计一下」。
3. **共用的键盘库。** user 2026-11-11：「把这个 Medo键盘给抽成一个共享库」。家族里另一个要接 MIDI 琴的项目当时回的是：它只要「接 MIDI 琴」那一小块，不要屏幕上的键盘。

这一轮不做的（记着，没有丢）：

- 鼓的输入键盘、和弦键盘。这一轮把结构留好，它们以后各是「另一面格子」。
- MIDI 琴的力度和踏板真的用起来（现在按下多重都一样响、踏板不接）。库这一轮把数递出来，app 接不接另算。
- iPad 和手机上键盘的位置。照旧贴底。
- 屏幕键盘要用的音乐知识（音阶、音名）不进库。见第五节。

## 二、现在的键盘是什么样（读代码看到的）

- 键盘本体一个文件，约 770 行。它已经不碰谱：音键上写什么字、「1=」有哪些档，都是外面算好递给它的。这是 user 2026-10-14 定的：「键盘确实是前端，音乐知识比如和弦有几个是外部注入的…键盘只管交互状态机，它不懂音乐」；2026-11-07：「medo的接口要窄，宿主给他提供各种信息」。
- 但有四样东西还写死在键盘本体里：
  - 长短旋钮的六档（三十二分到全音符）。所以它没法跟着拍号变。
  - 写字那一排有哪几颗键、各叫什么。
  - 符号格每一格的图、名字、说明。
  - 所有界面上的字和图标。
- 键盘摆在哪，是页面的格子布局定的：贴底，谱面只剩一行时改贴右。没有「浮着」这一种。
- 接 MIDI 琴的那一块（约 120 行）已经是干净的：不碰界面、不带字。缺一样：踏板这类控制器的数它读了但不往外递。
- 键盘自己的布局（几行几列、首调还是绝对、滑是滚键盘还是升降）哪里都没记，每次打开都回到默认。

反映出来的结构：一块键盘其实是三层——**怎么按**（手指、旋钮、锁，通用的）、**有哪些键**（数据，每个 app、每种键盘不一样）、**键是什么意思**（翻译成命令，只有这个 app 懂）。现在第一层和第二层粘在一个文件里。这一轮三件事都卡在这里：档位要变成数据，键盘要能换地方放，别的 app 要能拿走第一层。

## 三、带附点的档

### 规矩（一条）

长短旋钮上摆的，是**这个拍号里一小节以内、用得上的时值**：

- 从现在的六档出发。
- 比一小节长的，不摆。
- 一拍是三个小的那种拍子（6/8、9/8、12/8、6/4），长过一拍、又不是整拍数的，不摆。
- 加上带附点的：这种拍子的一拍；一小节正好是一个带附点的音符时，加上它；12/8 再加半小节。

### 照这条规矩算出来的表

| 拍号 | 旋钮上的档（短 → 长） |
|---|---|
| 4/4、2/2、5/4 | 和现在一样 |
| 3/4 | 三十二分、十六分、八分、四分、二分、**附点二分** |
| 6/8 | 三十二分、十六分、八分、四分、**附点四分**、**附点二分** |
| 9/8 | 三十二分、十六分、八分、四分、**附点四分** |
| 12/8 | 三十二分、十六分、八分、四分、**附点四分**、**附点二分**、**附点全音符** |
| 3/8 | 三十二分、十六分、八分、四分、**附点四分** |
| 6/4 | 三十二分、十六分、八分、四分、二分、**附点二分**、**附点全音符** |
| 3/2 | 三十二分、十六分、八分、四分、二分、全音符、**附点全音符** |
| 2/4、7/8 | 少一个全音符（它比一小节长） |

- 3/4：全音符那一档换成附点二分（一整小节）。二分留着。
- 6/8：二分、全音符换成附点四分（一拍）、附点二分（一小节）。四分留着（四分加八分是 6/8 最常见的写法）。
- 副作用：2/4、7/8 里全音符那一档没了。要写两小节长的音，用二分加「—」。

### 别的几处怎么算

- **跟着哪里的拍号**：光标这里、这个声部的拍号。没有手动档。
- **光标走进另一种拍号**：正选着的那一档**不变**，哪怕它不在那个拍号的表上。旋钮上照实显示它，点开的滚轮里也有它；人拨一下旋钮，才落到表上相邻的一档。软件不替人换档。
- **「/2」（减半）**：就是长度的一半。附点四分的一半是附点八分。普通的档上和现在一样。不到三十二分的减不了，和现在一样。
- **「—」（拉长）**：照旧，加一份现在的档。「/2 开着按 — = 附点」那条路留着，没变。
- **连音**：带附点的档不和连音一起用。选了带附点的档，连音回到「不连」，说一句。
- **电脑键盘的 8、9**（短一档、长一档）：沿着这个拍号的表走。
- **键面上**：音符后面一个附点。提示字写「附点四分」。
- **存进歌里**：歌记着长短旋钮上次停在哪个时值。那一项现在能写的是六个音符的名字；多认带附点的时值的名字（附点四分、附点二分…）。**不加新的键，没有「带不带附点」这个标记。** 这是 app 存歌时顺手记的、视图那一侧的东西，改了它声音不变。
  - user 2026-11-13 夜看了第一稿（多记一样「带不带附点」）：「为什么，键盘应该不知道乐理，乐理用app提供，它不知道附点 是什么。顶多知道时值」。第一稿是统筹图省事在音符名旁边加一个标记，形状不对：停在哪一档就是一个时值，记时值本身。

### 谁懂乐理

- user 2026-11-13 夜：「3/4、6/8 下带附点的 没问题，不过记得medo不懂乐理哦，深模块窄接口分工做好」。
- 键盘本体只知道：长短旋钮上有一串档，每一档有一个图、一句提示字；现在选着第几个。人拨了旋钮，它报「选了第几个」；人按了「/2」「—」，它报按了哪颗键。
- 键盘本体不知道：拍号、附点、复合拍子、哪些长度合法、减半之后是多长。这些全在 app 那一侧——那一串档是 app 按光标处的拍号算好递进来的，和「1=」、调式的档走同一个口。
- 所以第一版（带附点的档）在键盘本体里只做一件事：把写死的六档拿掉、改成向外面要。带附点的规矩、那张表、提示字都在 app 那一侧。这一步不等第四版。

## 四、超大屏上的键盘：浮窗

### 和以前说法的关系

user 2026-10-21 说过：「ui默认键盘在下面，就是很长很宽的屏幕，键盘，混音台，都在下面」。2026-11-12 看了 4K 屏的样子之后要浮窗。这一稿的读法：贴底还是默认；只有宽到键被拉得又宽又扁的屏幕，键盘才浮起来。混音台不变。

### 做法

- **什么时候浮**：谱那一块宽过 1600（屏幕上的像素，不是物理像素）。最大的 iPad 横过来是 1376，所以 iPad 永远不会自己浮。全屏的 1080p 显示器（1920）会浮。
- **能改**：键盘「⋯ → 布局…」里加一行「位置：自动 / 贴底 / 浮窗」。默认自动。想在 iPad 上浮、想在大屏上贴底，都可以自己选。
- **样子**：键盘照它舒服的大小（默认约 560 宽，写字那一排所有键都露着）浮在右下角。左上角一个圆把手，按住拖到哪算哪；右下角能拉宽。几行几列还在「布局…」里调。
- **模式条跟着窗走**：「音 / 词 / 听」和播放那一条贴在浮窗上沿，一起动。键盘收起时它回到屏幕左下角，和现在一样。
- **收起**：还是键盘上那颗「收起」，再开回到原来的位置。不另加「缩成小图标」那种收法，免得两种收法打架。
- **混音台不浮**：它要的就是宽，照旧贴底。所以「听」里和现在一样。
- **谱让路**：光标那一行被浮窗盖住时，谱自己往上滚到露出来。别的时候不动。
- **记在这台设备上**：浮窗的位置和宽度、「位置」那一项。换设备不跟。
- **顺手**（统筹加的，user 没提）：键盘的几行几列、首调还是绝对、滑法，现在哪里都没记。趁这次一起记在这台设备上。
- iPad、手机：不变。

## 五、共用的库

### 分成两个，这一轮都留在仓里

**第一个：接 MIDI 琴。这一轮做成项目里的一个模块，名字 MIDI input（文件夹 `midi-input`）。不新建内部库。**

- user 2026-11-13 夜（语音转写，原样）：「只有一个用户的时候是内某模块，可以叫Midi input」。统筹的读法：「内某模块」= 内部模块；只有一个用户时它是项目里的模块，不是家族内部库；名字叫 MIDI input。
- 统筹第一稿写的是「这一轮就出库，现在就有两个项目要用」。照 user 这句收回：另一个项目当时说的是不急、先用它自己的最简版，所以现在真在用这一块的只有写歌软件一个。
- 内容 = 现在那一块，加上把踏板这类控制器的数原样递出来。
- 只做一件事：琴上哪个键按下、多重、哪个键松开；琴插上、拔掉；浏览器给没给许可。不碰界面，不带任何字，不依赖别的东西。
- 力度照 MIDI 原样给（1 到 127），不替人换算。
- 模块的文件夹不引用它外面的任何文件，有守卫看着。以后出库就只是搬文件夹。
- 什么时候出库：第二个项目真来拿的那一天。到时候新建内部库照家规先问 user，把打包出来的真实接口交给他过目。

**第二个：键盘本体。这一轮在仓里切干净。它也只有一个用户，照 user 同一句：是项目里的模块，不出库。名字待定。**

- 名字：user 2026-11-13 夜「等我想个好听的名字，现在先名字待定」。他起之前文件夹留在现在的位置（`src/keyboard/`），不起新名字、不改引用；起了再搬。

- 做法：键盘本体只留「怎么按」。有哪些键、键上的图和字，全部变成外面递进来的数据（一张「这块板上有什么」的表）。写歌软件自己的那张表搬到 app 这一侧，和「键是什么意思」放在一起。
- 切完之后，键盘本体那个文件夹不引用 app 里的任何东西，有守卫看着。出库就只是搬文件夹。
- 为什么不现在就出库：
  - 它只有一个用户。只有一个用户时定下来的接口容易歪，库的版本号花出去就收不回。
  - 写歌软件自己已经有三种键盘可以拿来验这张表：写音的、符号格、只弹不写的（找乐器、即兴）。先让这三种都从同一张表画出来。
- 什么时候必须出库：第二个项目真要屏幕键盘的那一天。到时候统筹来看。

### 它以后会长成什么

- 鼓的键盘、和弦键盘、给小朋友的大键盘：各是一张新的表，不是键盘本体里新的分支。
- 「没意义的键灰掉」那张表、键上的字跟着谱种走，已经是外面给数据、键盘照着画。这一轮把剩下写死的四样也收成同一种做法。

### 不进库的

- 音乐知识（音阶、音名、第几级是什么音）。键盘不懂音乐；写歌软件的这一块和谱的核心是同一份，不能倒过来让谱去依赖键盘库。
- 第二个项目要屏幕键盘时，音乐知识那一小包从哪来，到时候再定。那时有两个用户，才看得出它该长什么样。

## 六、分几版

一波一个版，照这个顺序：

1. **带附点的档。** 看得见。小。
2. **浮窗，加键盘布局记在设备上。** 看得见。小到中。
3. **接 MIDI 琴的模块（MIDI input）。** 看不见（踏板的数先不用）。小。
4. **键盘本体切开。** 看上去没有变化。中。靠现有的键盘界面测试守着手感。

第 1 版里长短旋钮的档已经改成外面给，第 4 版不用返工。

## 八、给施工的细则

### 8.1 带附点的档

- 输入状态里记**长度**，不记第几档。现在 `InputState.unit` 是 `LADDER` 的下标；改成记这一档的长度（tick）。名字换掉（同一个名字的意思不变）。`unitDur` 照长度算，连音照旧乘比例。
- 表从哪来：`src/score/` 一个纯函数，吃拍号（几拍、以几分音符为一拍），吐这一小节的档（长度 + 是不是附点 + 底下那个音符是哪一种）。算法 = 第三节那四句；对照表 = 第三节那张，逐行进单元测试。
- 旋钮：键盘本体里的 `UNITS / UNIT_GLYPH / UNIT_NAME` 拿掉，改成向宿主要（同 `keyChoices` 的样子：每一档的图、现在第几档、提示字）。正选着的长度不在表上 = 宿主把它按长短插进这一串里。
- 连音滚轮里画的小蝌蚪现在吃档的下标，改成吃底下那个音符是哪一种。带附点的档：连音那一列灰着、点了说为什么（照「没意义的键」的做法）。
- `/2`：`main.ts setHalf` 现在是下标减一；改成长度除以二，除不了（结果不是合法的时值）= 不动。「两个凑满一份」照旧。
- `shorter / longer`（电脑键盘 8、9）：沿这个拍号的表走；不在表上的长度 = 往那个方向找最近的一档。
- `setSelDur` 这类吃档下标的口一起改成吃长度。
- 歌文件：**不加键。** `view.pad.unit` 记的是长短旋钮停在哪个时值、值是时值的名字；能写的值从六个音符名扩成「六个音符名，或者前面带 `dotted-`」（`dotted-quarter` = 附点四分；`src/score/desk.ts` 的 `PadUnit` / `PAD_UNITS` 跟着加）。
  - 读：不认识的值不理、用模板的默认（现在就是这样，不改）。存：选着的长度是哪个名字就写哪个；选着的长度没有名字（不该出现；出现了）= 这一项不写、说一声进黑匣子，不猜一个近的。
  - 老版本的 app 读到新文件里带 `dotted-` 的值：不认识、旋钮落在默认的八分，不坏。
  - 没有新键，形状快照不用重冻；`test/desk.test.ts` 加一条带附点的值来回一遍。
  - 长度和名字互相换算只在 app 那一侧一处（和算档位表的那个纯函数放一起）；键盘本体里不出现 `dotted`、不出现音符名。
- 守卫：照表逐行；随机拍号下「旋钮上每一档写下去都是合法的时值」；「光标跨拍号，选着的长度不变」；`/2` 在普通的档上和改前逐一相同。

### 8.2 浮窗

- 放哪儿的判断只在一处：`src/app/workspace.ts`，和 `sideDock` 放一起，一个纯函数回「贴底 / 贴右 / 浮」。`test/dock-layout.test.ts` 那条规矩照旧（CSS 里不许按尺寸分底座）。
- 浮窗的壳用界面零件库现成的 `registerFloatingWindow`（圆把手拖、右下角拉宽 `axis: "x"`、钳在视口里）。不开它的「收成小图标」。
- 键盘本体不许再量整个窗口：`padForm()`、`rows()` 现在用 `innerWidth / innerHeight`，改成量自己的容器（宿主告诉它，或者它量 `el`）。
- 浮着的时候谱按「没有底座」排版。
- 谱让路：`ScoreView` 的跟随多认一块「被盖住的矩形」，只管光标那一行。

### 8.3 接 MIDI 琴的模块 MIDI input（接口草稿）

住 `src/midi-input/`（从 `src/keyboard/midi.ts` 搬出来）。项目里的模块：不出包、不新建内部库、没有版本号。

```ts
/** 一条消息里用得到的。数都是 MIDI 原样的：note 0–127（60 = 中央 C），velocity 1–127，value 0–127，ch 0–15。 */
export type MidiMsg =
  | { k: "on"; ch: number; note: number; velocity: number }
  | { k: "off"; ch: number; note: number }
  | { k: "cc"; ch: number; cc: number; value: number };
export function parseMidi(data: ArrayLike<number>): MidiMsg | null;

export type MidiStatus =
  | { k: "unsupported" } | { k: "off" } | { k: "asking" }
  | { k: "denied"; why: string } | { k: "on"; inputs: string[] };

/** 哪台琴、哪个通道。 */
export interface MidiFrom { port: string; name: string; ch: number }

export interface MidiHandlers {
  /** id = 这一下的来源，松开时同一个。 */
  down(note: number, velocity: number, id: string, from: MidiFrom): void;
  up(id: string): void;
  /** 控制器原样递出来（踏板 = 64）。不给 = 不要。 */
  control?(cc: number, value: number, from: MidiFrom): void;
  plug?(name: string, on: boolean): void;
  status?(s: MidiStatus): void;
}
export interface MidiInput {
  readonly status: MidiStatus;
  /** 人点了「连接」才调：会弹浏览器自己的许可框。 */
  connect(): Promise<MidiStatus>;
  /** 开 app 时调：浏览器记着「允许」就静默接上，没记着什么也不做。 */
  resume(): Promise<void>;
}
export function createMidiInput(h: MidiHandlers, nav?: MidiNavigator): MidiInput;
```

- 和现在的差别：力度从 0–1 改回 MIDI 原样；多 `control`；多 `from`；改名（不再叫 keyboard，它不是键盘）。
- 行为照现在的，一条不少：任何通道；按下力度 0 = 松开；同一个键没松又按 = 先松再按；拔掉 = 它按着的都松开；开 app 不弹许可框。现有 9 条单元测试原样搬过去。
- 守卫：`src/midi-input/` 里的文件不许引用这个文件夹外面的任何文件。
- 写歌软件这一侧：`main.ts` 那一处接线改用新名字；`control` 先不接。

### 8.4 键盘本体切开（接口草稿）

宿主每次重画给一张表，键盘照着画；键盘往外只报「哪颗键、怎么按的」。

```ts
/** 这块板上现在有什么。纯数据。 */
export interface Board {
  head: HeadItem[];              // 最上面一排，从左到右
  tools: ToolKey[];              // 写字那一排
  face: NoteFace | CellFace;     // 格子那一面
}
export type HeadItem =
  | { kind: "knob"; id: string; html: string; title: string; tags?: { text: string; title: string }[] }
  | { kind: "tab"; id: string; html: string; title: string; on: boolean; badge?: string }
  | { kind: "button"; id: string; html: string; label: string; title: string; on?: boolean };
export interface ToolKey {
  id: string; html: string; small?: string; title: string;
  /** tap = 点一下；repeat = 按住连发；hold = 按下、松开各报一次；slide = 按着上下滑换一种。 */
  press: "tap" | "repeat" | "hold" | "slide";
  lit?: "once" | "lock";
}
export interface NoteFace { kind: "notes"; hint: { lo: number; hi: number; title: string } | null; ring?: readonly number[]; acc: number }
export interface CellFace { kind: "cells"; page: string; cells: Cell[] }
export interface Cell { id: string; html: string; label: string; title: string; lit?: "on" | "once" | "lock"; dim?: { tag: string; tip: string } }

export interface PadHost {
  board(): Board;
  /** 旋钮的档：一列或两列。 */
  choices(knob: string): { items: string[]; index: number; loop?: boolean; title: string; width?: number }[];
  /** 音键上的字（照旧宿主算）。 */
  cell(k: number): PadCell;
  altered(k: number, a: number): KeyFaces;
  anchor(layout: "absolute" | "movable"): number;
  sig(): string;
  /** 这颗键现在为什么没意义（null = 有意义）。 */
  offWhy?(id: string): string | null;
  onOff?(why: string): void;

  onNoteDown(k: number, id: string): boolean;
  onNoteUp(id: string): void;
  onAlter(id: string, alt: -1 | 0 | 1): void;
  onKey(id: string, how: "tap" | "repeat" | "down" | "up" | "slide", value?: number): void;
  onPick(knob: string, column: number, index: number): void;
}
```

- 这是草稿。施工方第一步：照现在 `pad.ts` 里每一颗键、每一种按法列一张对照表，看这张草稿装不装得下；装不下的报统筹，不自己加口子。
- 搬到 app 这一侧的：写字那一排的键、符号格三页每一格的图和字、「⋯」里的候选、所有 `_t()` 和图标、`keys.ts` 的提示字、布局对话框。
- 留在键盘本体的：格子怎么按（按下、松开、滑到下一个键、上下滑升降、几根手指）、旋钮（原地滚、点开滚轮、鼠标滚轮）、按住连发的节奏、锁的规则、几行几列和键的大小、没意义的键那一道拦、只在结构变了时重建。
- 「渐到」那把锁现在住在键盘本体里，是写歌软件的东西：搬到宿主。
- 守卫：键盘本体的文件夹不许引用它外面的任何文件（现有「不引用谱」那条扩成这一条）；键盘的界面测试一条不改、全绿，才算「看上去没有变化」。
- 这一版不升内部库、不出包。
