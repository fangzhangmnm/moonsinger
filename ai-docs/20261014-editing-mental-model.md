## 1. 四个模块 + 锁

- **「我觉得后期应该是音 词 唱 听 四个模块，以及还有锁的问题」**（10-14）。
  - **音** = 写音（音 / 休止 / 小节线、记号——「音和符应该可以一起编辑」10-10；「音和符应该只是是个模式…不应该用模式来切」10-10）。
  - **词** = 写歌词（iOS 键盘）。
  - **唱** = **录音纪元的东西**（10-14「唱说的是录音纪元的东西，你可以想一下audacity」）：user 自己唱 / 录进去的那一块，不是月读唱。远景文档 `20261013-vision-epochs-and-refactor.md` 的录音纪元。
  - **听** = 锁住谱只听 + 混音台（10-10「还有一个就是播放模式，锁写谱，但是可以调录音室」「能不能混音台就是听的键盘」）。
- **锁** = 键盘上那几把 Shift 式 / caps 式的东西（/2、升降、渐到、符 / 音、叠）——「键盘自己的状态机比如/2 这种，到底看的是上个音还是完全不看的一个状态机，把内部状态和输入输出好好定义好窄接口不就得了」（10-14）。

## 2. 键盘的本质

- **「键盘应该是纯前端」**（10-14）→「aha，屎山，那些音乐知识怎么办」→ 定稿：**「键盘确实是前端，音乐知识比如和弦有几个是外部注入的，所以一个键盘的前端库，一个是负责生成音乐知识的深模块。以后我们马上要做和弦键盘，也是一样的」「然后出来的也是按键而不是和弦，翻译成音符输入别的人管。键盘只管交互状态机，它不懂音乐」**（10-14）。
- **几个键盘**：「现在我们有了好几个键盘。我现在倾向于音 符 是独立的，然后词我也需要有输入-和+之类的键盘，这个应该在ios键盘弹出的时候输入到一半也能工作的」（10-14）。
- 老话（还算数）：「keyboard不应该用flex，这是一个很固定的有着很严密逻辑的东西」（10-07）；「pad 像软键盘、五线谱像文本框」（10-07）；「软键盘里面后面有一个符号模式…row col 超了可以拖动滚」（10-08）；/2 / 升降 = Shift 逻辑（点一下 / 连点锁 / 按住）、符 = caps（10-07 / 10-09）；叠 = 锁定式（10-10「叠音模式也应该只有capslock没有shift」）。
- **W-5（UI 的深模块：旋钮 / 推子 / 滚轮…）和这个是一回事**（user 10-14「这个可能和我们的屎山周工作有关系」）：键盘前端库 = 键 + 锁 + 旋钮 + 推子 + 滚轮这些交互原语，`param-row.ts` / `wheel.ts` / `drum.ts` 已经是零碎的雏形。

## 3. 引擎 = 指令式，两层各一道护栏

- 远景（10-13）：「全指令式…要把这个逼出来…至少你写testsuit会方便很多」；「如果有一个无头的node端的moonsinger你或者gpt6也可以用手指操作去写歌听歌画画迭代，而不是直接hack源文件」。
- 10-14：**「还是按照指令式做，然后ui和指令式引擎各护栏一次。指令时引擎的护栏会报错，然后我们好好错误处理」**。
  - UI 层的护栏 = 不让你点出不合法的东西（灰掉 / 不接）。
  - 引擎层的护栏 = 收到不合法的指令就**报错**（不崩、不静默吞），UI 把错误好好处理成人话。两层都在，UI 漏了引擎兜住。
- 和 10-13 memory 的「撤销体系两条契约」同一精神：调用者 abuse 能按规章定义给要的结果，而不是自己崩。

## 4. 不变量

- **音游级延迟**（10-14「不变量还有音游级延迟的需求」）：按键 → 出声那条路不能排在任何重活后面（排版 / 重画 / 唱法核心都不许挡它）。和 10-04 的「键盘不被 app 卡 = 结构隔离，不是优化 app」一致：先想谁等谁、分道。
- 已有的：鬼音符 / 预听「千万不能动排版」（10-10）；听模式只锁输入不锁视图（10-10）；做不到的一律画灰 + 明说（10-08 纪律）。

## 6. 推出来的形状（AI 推荐稿，user 10-07「fable的任何数据结构契约都只是推荐稿」）

```
┌─ 键盘前端库（纯前端，不懂音乐；= W-5 + 锁）────────────────────────────┐
│  Key（一个键：id、位置、label 由外面给）  Latch（off/once/lock/held 一条规则）  │
│  Knob / Fader / Wheel（param-row / wheel / drum 收进来）                    │
│  输出 = KeyEvent { key, phase: down|up|slide, latches: {...} }（按键，不是音）│
└──────────────────────────────────────────────────────────────────────────┘
          │ 布局 + 标签 + 「这键代表第几级 / 哪个和弦」            ↑ 注入
┌─ 音乐知识深模块（纯函数）──────────────────────────────────────────────────┐
│  scales / 调式梯子 / 和弦有几个音 / 首调数字 / 音域提示   （现在的 scales.ts、以后的和弦表）│
└──────────────────────────────────────────────────────────────────────────┘
          │ KeyEvent → Command（翻译层：「按键 + 当前锁的状态 + 光标 / 选区」→ 一条指令）
┌─ 指令引擎（唯一入口；护栏 = 不合法就报错，不崩不吞）─────────────────────────┐
│  apply(state, Command) → state | throws CommandError{ why }   （commands.ts 扩成唯一入口）│
└──────────────────────────────────────────────────────────────────────────┘
          │ 错误 → UI 说人话（toast / 画灰）；合法 → update() → 出声 **先**于重画
```

- 模式只剩 **音 / 词 / 听**（+ 以后「唱」）；「符」= 音键盘翻面，不是模式。
- 翻译层是新的一小块（现在散在 `main.ts` 的 pad 回调 `onPitch / onCommand / onHalf / onAccShift…` 里），它是唯一懂「锁 × 光标 × 选区 → 指令」的地方。
- /2 这把锁**不看上一个音**：它只改「接下来写多长」这一个输入参数（半份），写进去的那一下由翻译层按谱算附点 / 凑满；锁自己只有 off / once / lock / held 四态（§7 要 user 确认）。
- 和 F-17 策划稿的关系：策划稿第 2 期（锁的纯函数）= 这里的 Latch；第 1 期（盖层登记）不变；第 3 期（手势联合）是谱面那一侧，不在键盘库里。

## 8. user 的回答（2026-10-15 上午，原话；edited by Claude Fable 5.1）

1. /2：「/2建议是键盘的状态机」→ **看输入**（下一次按键），不看谱；和现在的代码一致。
2. 唱：「类似sampler轨，一个轨可以放很多波形，但是还是用note来处理对齐和时长，但是也可以微调trim，note=对齐和窗口，类似蒙板和anchor，但你也可以pushback，或者不用Note还是用小节号定位？因为我们说了不用绝对时间。两个waveform重叠了怎么办 / 反正绝对是演奏者」→ **唱 = 演奏者**（ADR-0004 §2.3 `performer:recording`），一轨多片，**音 = 锚 + 窗口**。AI 的推荐稿（user 没反对，还没拍）：片 = { 锚在哪个音（token id）, trim（片内起点秒）, 增益 }；窗口 = 到同轨下一片的锚为止（蒙板），重叠 = 后锚的盖前一片（交叉淡 ~20 ms），前一片的尾巴在下一片锚之前照响（= 一段段补录天然是 comping）；不用小节号（弱起 / 反复里歧义，音才是谱的时间尺）。代价先说明：片是定速音频，锚跟谱走、内容不跟速度拉伸，录完改速度长片尾巴会错位（DAW 同）；真要跟 = WORLD 分析再按谱重合成（把人声走小月相那条路），另一件事。
3. 词键盘：「合也可以加，标点符号其实我不会用。但也可以加如果你教我怎么用的话」→ 键 = **− / + / 合 / 标点**。标点的用法（教）：歌词框里字后面打 `。．，、,.!?` 任一 = 那个音后面放「句」记号（歌词行里小灰「。」，不占时值、不换行、不换气、不进 MusicXML），**唯一作用 = 「合」挪字到此为止**；小月相断句看休止不看它。
4. 键盘库：「这个是项目内部库，是要抽库，我记得是有家族库和模块两种方式，这个更像是模块」→ **项目内部模块**（`src/keyboard/` 这一级），不出 `@internal/*` 家族库。
   - 2026-10-15 追加（user）：「但是其实也有点晕，因为我一开始想的是谱子显示的还是五线谱，然后只是小月相换成你，然后五线谱上面显示waveform，这个可能和是音符打架，所以应该还是不是音符吧」「喵喵歌的话是另外一种模式就是采样器驱动的音符」→ **录音不是音符**：谱照旧是五线谱（写的是该唱什么），录下来的片是演奏者的数据，锚在音上只是借谱的时间尺；波形画在那位那一行的底层（和播放时的小节底色同一层，不进排版）。**两种模式**：① take 模式 = 一段段录进来锚在音上（块那条路，像小月相）；② 采样器模式 = 录一声当采样、音符触发按音高变调（音符表那条路，像 SoundFont / 元音版）——喵喵歌。
