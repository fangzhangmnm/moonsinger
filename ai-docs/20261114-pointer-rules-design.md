## 二、这一版要变的规矩

下面第 1、2 条是 user 说的；第 3–6 条是统筹配的默认，做出来由 user 判。

> **2026-11-14 凌晨 user 批了一处**（看了统筹报给他的「鼠标和手指现在差在哪」那张表之后，原话：「你说的这张对照表里面的修改意见，我觉得可以」）。那张表里标着要改的只有一行——音和选区的菜单：鼠标「右键、长按」改成只右键，手指「长按」改成小钮。所以第 3 条里「长按音 / 休止不再开菜单」这一半算 user 批过的。「长按 = 选中它，和点一下一样」、第 4 条小钮的细节（什么时候出、摆在哪）、第 5、6 条，他没有单独说，仍是统筹的默认，做出来由他判。edited by Claude Fable 5.2

1. **选中不弹菜单。** 点一下、长按、拉框、拖把手、Shift 扩选，哪一种选法都不自己弹菜单。
2. **叫出菜单要明着的一下**：鼠标 = 右键；手指和笔 = 选区旁边的一颗小钮。
3. **长按音或休止 = 选中它，和点一下一样，不开菜单**（鼠标、笔、手指都是）。已经选中的再长按 = 不变。取代选中规则设计稿第五节第 6 条里「按在音上 = 先亮框再开选区菜单」那半句；记号和空白那两半句不动（记号 = 它的小菜单；空白没有选区、没处挂钮，手指长按照旧出空白菜单）。
4. **小钮**：
   - 有选区（一个、一段、多行的块）、最近一下是手指或笔时才出；鼠标不出（鼠标有右键，选区条上也有「操作…」）。
   - 贴着选区带子的右端、在带子外面；不盖符头、不盖拖的把手。选区跨行 = 跟最后一行的右端。
   - 屏幕上够手指按（不随谱面缩放变小）；只在编辑器里画，不印。
   - 点它 = 开的就是现在的选区菜单，内容一项不改。
5. **菜单不盖选区的带子**：先试带子下面，放不下试上面，再试左右；都放不下才允许盖。右键、小钮、选区条的「操作…」三条路都照这条摆。
6. 选区条上的「操作…」留着不动（要不要拿掉等 user 看了小钮再说）。

## 五、模块的口

现在的毛病（结构上的）：问「是不是手指」有三种问法，各问各的——按这一下的指针（`e.pointerType`，谱面里十来处）、按这台设备（`matchMedia("(pointer: coarse)")`，三处 + 样式表）、按最近一下（`main.ts` 的 `touchLike`）。iPad 接了鼠标、电脑带触屏时三种问法答案不一样。

收成两层，都是纯函数：

1. **`src/ui/pointer.ts`（全 app 共用，很小）**
   - `type Pointer = "mouse" | "pen" | "touch"`；`pointerOf(e)` = 全 app 唯一一处读 `e.pointerType` 的地方。
   - `caps(p)` = 第三节那张表：`{ hover, secondary, wheel, dragScrolls, coarse, softKeyboard }`。
   - `lastPointer()` = 最近一下用的是哪种（取代 `touchLike`）。没有事件可问的事（画不画小钮、画不画把手）问它。
   - 规矩：模块外面不许再比 `pointerType`、不许再问「是不是手指」；只许问能力（`caps(p).hover`）或者问下面那一层要结论。样式表里的 `pointer: coarse` 只许管大小，不许管行为。
2. **`src/ui/press-rules.ts`（谱面这一块，已经有了，长成这一层）**
   - 进去的：哪种指针 × 做了什么（轻点 / 按下后动了 / 按住不动 / 第二个键 / 悬停）× 按在什么上（音、记号、演奏法、空白、把手、小钮）× 当时的状态（亮没亮、在不在选区里、这个模式和修改锁让不让拖）。
   - 出来的：一个结论（亮框、选中、放光标、开哪个菜单、拖、拿起来挪、拉框、滚动、什么都不做），和「旁边要画哪些零件」（把手、小钮）。
   - 现成的 `onTap` / `onMove` / `isLit` / `wantsGrip` 留着；加「按住不动」「第二个键」两个问法和「画不画小钮」。谱面视图只照结论办，不自己判。
3. **守卫**（`test/` 里一条）：`src/` 里比 `pointerType`、问 `pointer: coarse` 的地方数出来写成名单，每处写归第三节哪一件；只许减不许增；`pointer.ts` 之外新出现 = 红。

## 八、长按不再拖（v0.17.57）

> added 2026-11-14 by Claude Fable 5.2（MoonSinger统筹）。和前面几节冲突的地方以这一节为准；施工方做完把第四节对应的格子改过来。

**user 的话**（2026-11-14 凌晨，语音，原样）：

- 「嗯，同意，三种都长按拿起来拿，笔的手感会变，因为笔一拖其实就不大好，以及长按，我觉得现在是不是长按都可以不要了，长按就变成就是长按拖动这个是之前会出很多东西的问题，以及词里面按住一个字拖这个交互能不能 sunset 日落掉，换成别的更合理的超交互，就是说我觉得。长按拖都变成点一下选中，然后拖，会不会好点？」
- （统筹报了下面五条之后）「然后这些修改你是能合并到当前单子就尽量合并到当前单子。」统筹的读法：五条照做。方向（长按再拖拿掉、「词」里挪字换成点一下选中再拖）是 user 自己提的；五条的写法是统筹配的，其中第 2 条的代价（手指改一个已有的字多点一下）user 没有单独表态，做出来由他判。

- （看了五条之后）「长按是手指板的右键同义。然后拖只有一种，点一下拖中同意。对，我说的不要是长按再拖，但是右键的长按可以。然后词的合并用拖动合并，其实相当难操作，我们还是改成小按钮，就选中之后改成小按钮。然后是，反正你快点做吧，多快好省着做。这些都是一些比较小的 UX 修改，就是一口气做好，就在这个版本做。」（「同义」= 同意，「拖中」= 选中，语音。）第 1、5 条他明着同意了；第 2 条照这句话重写。

**五条规矩**

1. **拖只有一种：先选中（点一下），再拖。** 鼠标和笔直接拖亮着框的；手指拖框边的把手。没有「长按再拖」，没有「按多久算哪一种」。
2. **「词」里有字的字：选中之后旁边出两颗小钮，不拖**（user 同一晚改的：「然后词的合并用拖动合并，其实相当难操作，我们还是改成小按钮，就选中之后改成小按钮。」这一条的第一稿是「字和记号走同一张表、亮着拖 = 挪」，作废）：
   - 点一下有字的字 = 选中它（亮框），旁边出两颗小钮。三种指针一样；鼠标悬停不点亮字。
   - 左钮 = 往前一个音。前一个音有字 = 钮上写「合」（并成一个音上几个字，这一句后面的字往前挪一个音）；前一个音空着或是拖腔 = 钮上写「←」（这个字早一个音起）。
   - 右钮「→」= 往后一个音（后面的字被推着走；合过的 = 拆出最后一个字）。
   - 走不动的那一颗画灰，点了说为什么。点完，字到哪，亮框和两颗钮跟到哪，可以连着点；每点一下是撤销里的一步。
   - 亮着再点字 = 开歌词框改字（歌词框自己那颗「合」不动）。长按字 = 和点一下一样。
   - 不变的：点音头 = 开这个音的歌词框；点空着的歌词位、拖腔位 = 开歌词框；空着的位长按 = 空白处的菜单。
   - 两颗钮摆在字的正下方，屏幕上的大小不随谱面缩放，印出来的样子里藏；锁着、不让改的时候照修改锁现成的做法画灰。
   - **不能碍着写词**（user 同一晚：「这个小钮的位置不能干扰写词，可以吧？它遮下面的东西比如下一行铺子倒无所谓，但是不能干扰写词。」「铺子」= 谱子，语音）：两颗钮整个在歌词那一行的下面，不盖这一行的任何字、不盖上面的五线和音头，往下盖到下一行谱没关系；歌词框开着的时候（正在打字）一律不出，一开歌词框就收；点钮不抢焦点、不动系统键盘；钮出着的时候点别的字、音头、空着的歌词位照常是点它们。
   - 两颗钮各是什么（合 / ← / →、摆在哪、灰的时候怎么说）是统筹配的，user 只说了「选中之后改成小按钮」；做出来由他判。
3. **「词」里长按音 = 选中它**（照旧：那里点一下是写歌词，长按是唯一的选中办法）。「不抬手接着拖 = 扩选」拿掉；扩选用选区两端的把手，和别的模式一样。
4. **记号长按 = 和点一下一样**（没亮 = 亮框；亮着 = 它的小菜单）。右键照旧。
5. **长按只剩一个意思：手指的右键**，只在没有东西可选中、挂不了小钮的地方有：谱上的空白、听模式、走带钮、乐器目录、图标钮的说明。这一类不动。

**代码上**

- `press-rules.ts`：`Target` 加一种「字」——`onTap` 没亮 = 亮框、亮着 = 开歌词框；`onMove` 永远不是挪（鼠标和笔 = 拉框，手指 = 滚动）；`wantsGrip` 不出把手；另加一个问法「画不画字的两颗钮」。`onHold` 对记号、演奏法、字都 = 照 `onTap` 的结论办，对音 = 选中（已在选区里 = 不变），对空白 = 空白菜单。
- `score-view.ts`：`selDrag` 整个拿掉；「按住字拖」那条路（拿起字的那一支、借 `caps().hover` 分笔和鼠标的那一处）整个拿掉——第七节「归不进四件的」就此消失。挪字的算法（`src/score/lyrics.ts` 的 `moveSyllable`）不动，两颗钮各调它一步。
- 风格记号小菜单里那句「长按拖 = 挪到别的音上」核一下，照现在的规矩改。
