## 附 B. VST3 / CLAP 是怎么设计的（科普，Claude Fable 5.1 写，user 10-09 22:32 要的；不是决策）

**VST3**（Steinberg，2008 起；VST2 已于 2018 停发许可）。一个插件 = 两个对象：
- **处理器**（`IComponent` + `IAudioProcessor`）跑在音频线程：`setupProcessing`（采样率、最大块长、模式 = realtime / prefetch / offline）→ `setActive` → 每块一次 `process(ProcessData)`。`ProcessData` 里有：输入 / 输出**总线**（bus，每个总线几声道、可静音标志）、**采样精确的参数变化队列**（`IParameterChanges`：每个参数一列 `(采样偏移, 归一化值 0…1)` 点，插件自己插值）、**事件队列**（`IEventList`：note on / off 带 `noteId`、音高、力度、tuning；**note expression** = 每个音自己的音量 / 声像 / 弯音 / 自定义维度，靠 noteId 对上）。插件报告 `getLatencySamples`（前瞻造成的延迟，宿主补偿）和 `getTailSamples`（停音后尾巴多长）。状态 = `getState / setState` 一个**不透明的二进制 blob**。
- **控制器**（`IEditController`）跑在 UI 线程：参数表（名字、单位字符串、默认值、步数）、把归一化值变成显示文本、建 GUI；用户动旋钮 → `IComponentHandler.beginEdit / performEdit / endEdit` 回给宿主，宿主再把变化排进下一块的参数队列。
- 没有的东西：预热、按内容的缓存 / 失效、进度、取消、估内存、随机访问（「从第 37 秒开始出声」只能靠宿主从头喂或自己 seek）；离线模式只是个标志，不保证和实时同数学；状态 blob 没有量纲、没有自描述——这正是「插件宿主 = abandonware」那一条。

**CLAP**（2022，MIT，C ABI；Bitwig / u-he 牵头）。同样是「每块一次 process」，差别在：一切能力都是**可选扩展**（`params / note-ports / audio-ports / state / latency / tail / render / voice-info / gui / thread-pool / preset-load`…），宿主问「你有哪个扩展」；事件只有**一条按时间排好的队列**（note、note-expression、param-value、**param-mod**（临时调制，不改存的值）、transport）；每个函数标明 `[main-thread]` 还是 `[audio-thread]`；`render` 扩展明说 realtime / offline；`voice-info` 报复音数；`process` 返回 sleep / continue / tail 让宿主知道插件闲不闲。状态仍是 blob。

**对我们的意思（AI 的提醒）**：可借的 = 采样精确的事件队列、noteId + 每音表情、总线模型、延迟 / 尾巴报告、主线程 / 音频线程切分、realtime / offline 标志、参数单独一张自描述表。要多出来的 = 预热、内容键缓存 + 失效、进度 / 取消、估延迟 / 估内存、按时间范围出声（慢引擎才需要）、带量纲 + 自描述（vault）的参数与状态、离线 = 实时同一份数学。
