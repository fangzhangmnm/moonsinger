### 3.0 【数据安全 · 第一级 · 归 Fable · 比总闸和修改锁都先落地】自动保存在飞时换歌 = 上一首的内容写到新开那首名下（记账 2026-11-09 by Claude Opus 5.5；和家族周账 F-187「按存被吞」同一段代码）

家族根长跑会话（Claude Fable 5.1）11-09 转来；user 原话「顺手修的那个隐患也好好想想」。**Opus 不碰这个模块**（`src/editor-session/editor-session.ts`）。

- **是什么**：`persist()` 开头 `if (!_name || !need || _saving) return;`（有一轮在存，后来的调用直接返回、Promise 照常落地）；同一函数里 `await editor.encode()` **之后**才读 `_name` 去 `store.file(_name, …).save(…)`。叠起来：A 的自动保存在编码 → 开 B（open() 里「先存旧的」撞锁直接返回）→ `_name = B` → A 的编码完成 → **A 的字节存进 B**。A 最后几笔没存进 A；B 本机文件被盖，库的账上成了「有没传的改动」、会被补推。另一个后果 = F-187：人按存撞上在飞的自动保存，什么都没做就返回。MoonSinger 的 encode 在 worker 里、窗口比 WeebPaint 短，但自动保存更勤；`adopted()` / `release()` 同步，也能在窗口里换身份。**没有证据说实际发生过**（WeebPaint 同一段写法已用真模块复现、v0.14.66 修掉）。
- **修法（两处一起，缺一不可）**：① 排队——保存三个入口 / open / rename / delete / 定时器和监听排成一队，前一个落地才开始下一个，轮到时重新判断要不要做；② 钉身份——一轮保存起跑时记下名字和身份代数，字节只落到那个名字下，收尾改旗标前先对代数。全文和不变量 = 家族根 `ai-docs/20261109-editor-session-serialize.md`；参考实现 + 8 条回归测试 = WeebPaint `src/editor-session/editor-session.ts`（v0.14.66，提交 f854b27）、`test/editor-session-safety.test.mjs` 末尾那一组。
- **前提**：修之前确认 MoonSinger 的库传输层开了超时（推永远不返回会把队卡住，和以前 `_saving` 放不开同一个前提）。
- **谁、什么时候**：家族根原计划在修改锁那一轮一起修（那一轮本来要改这段的 `canPersist`）；如果这个会话先切到 Fable 做键盘总闸，由那时的 Fable 判断要不要**提前单独修**——它是第一级数据安全问题。

### 3.1 键盘总闸 = 把「拔插头 / 即兴」做完整（记账 2026-11-09 by Claude Opus 5.5；家族周账 F-194 前半；归 Fable，切到 Fable 时做）

家族根长跑会话（Claude Fable 5.1，在写 MoonSinger 修改锁迁移设计稿）11-09 转来 user 的话：「你直接给那个正在赶 Moon Singer 的 agent 给他发信息，让他记一下记账，然后到时候换到 Fable 的时候，让 Fable 好好处理一下」「就是相当于那边先做好键盘的总闸」。

- **这是什么**：所有输入之前一个地方，先回答「这一下归谁」「现在能不能往谱上写」（形状参考 CatsUp `ai-docs/20261105-input-gate-design.md`）。user 11-09：总闸和已有的「拔插头」（v0.16.13「弹 = 拔开的线」）是同一个功能——「我发现插头断掉的时候，你其他的一些像零啊、横杠啊这些东西还是有。所以说，其实那个拔插头的功能…没有做好」「在选乐器的时候，这些拔都是得做好」「键盘还是可以即兴的…你是一个钢琴轨，你在播放的时候，即使你被锁着，你键盘还是可以弹的，就可以跟着弹着玩」。
- **user 的三条要求**：① 拔着 = 所有会往谱上写的键都断开，不只是音符键（现在拔着时 0 / 横杠还会写）；② 选乐器的时候同样拔干净（按键只试音不写谱）；③ 锁着时插头强制拔着、接不回去，但键盘照样出声、放歌时能跟着弹（「不能写」≠「键盘没了」）。
- **修改锁那一轮（家族根 Fable）的要求**：① 「能不能写」只有一个回答、注入的：现在接 `D.locked()`，锁那一轮换成修改锁的回答；总闸里不另存「锁着 / 拔着」状态——「人自己拔的」「在选乐器」「歌锁着」三个原因合成一个现算的答案。② 每个输入动作带操作类别，和 `D.commit` 的 `locus.kind` 同一套词（score / paper / lounge / studio / cover）。③ 被挡下 = 安静不做 + 一个回调（以后「门闪一下」用），不每按一下弹错误、不做一半。④ 读的动作（挪光标、选中、复制、播放、导出、试音出声）永远不问「能不能写」。⑤ 「在框里打字时键归框」（W-36）收进这一处判。⑥ 这一轮**不动** `src/app/document.ts` 的锁语义和定稿四层、不加锁的界面（定稿退役换修改锁 = 家族根 `ai-docs/20261109-moonsinger-edit-lock-design.md`；user 已定：定稿取消换修改锁、曲段的隐藏锁着也能点、锁着时键盘照样能弹（插头强制拔着）；**mp3 去向 user 11-09 定了**：写歌完全不保管 mp3（歌库里不放、歌的文件里也不放；定稿连同嵌着的那份 mp3 机制一起退役；导出照旧是寄出去的一份），只在设备上记着渲过的结果当缓存（user「软件在设备上记着不就行了…相当于记着的是缓存同意」，「当年的声音」不留底），歌库卡片的 ▶ 和分享从这份缓存拿；「在歌库里不打开歌直接渲」user 想要、还没点头排期（家族根建议放在锁之后单独一轮）。原话 = 家族根 `ai-docs/20261109-moonsinger-edit-lock-design.md` 第 2 版第四节。（此前这里写过「未定」和「歌库里独立的文件」，都作废。edited by Claude Opus 5.5 2026-11-09））。⑦ 测试：判断是纯函数、单测；结构守卫——总闸以外不许再有直接听 keydown 改谱的路（盘点时 `src/app/*.ts` 有 9 处 keydown 监听）。
- **建议**（Fable 自己定）：先把「哪些键 / 钮 / 手势会写谱」列成明文表（拔着一律断，这张表以后就是总闸的数据）；pad 屏幕按钮和实体键盘走同一个判断。
- **顺序**：0.16 剩下的活 → 切 Fable 做总闸 → 家族根做修改锁。**做完在本清单留一句总闸的接口（「能不能写」从哪里注入），修改锁那一轮按它接。**

## 4. 施工纪律（都是这个仓踩过的）
