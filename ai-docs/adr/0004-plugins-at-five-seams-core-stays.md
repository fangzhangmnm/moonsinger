# ADR-0004 插件只挂在五处接缝、核心不插件化；小月相 = 注册表里的一项（guid + 英文名 + 版本）

> created 20261014 by Claude Fable 5.1 · status: **accepted**（2026-10-14 user 逐条拍，原话在 §1）· 屎山维护纪元（0.12）的宪法之一
> 来龙去脉：user 10-13「小月相也是插件，人类录音也是…两个 competing 方案」（`../20261013-vision-epochs-and-refactor.md` §3 ⑦）；10-14「所有的插件和小月读都插件化 这个我确实没有仔细grill，也许现在就是需要定的时间？」→ 本 ADR 就是那次 grill 的定稿。Opus 5.5 同日扫了本机四天会话：「全插件寻址 / 没有任何 builtin / 文件也插件化」这几个词此前没在任何记录里出现过，本 ADR 是第一次定。

## 0. 一句话

**插件只能挂在五处接缝——出声（演奏者）、效果器、文件进出、音源来源、（以后）显示的接口位；乐谱数据模型、时间线、录音房、指令引擎、键盘库是核心，不插件化。小月相的代码照样 vendor 在 app 里发，但在系统里只是注册表里的一项：代码里不许再有按引擎名的分支，一律问注册表。谱上记的是乐理里的 role（二胡），演奏者是顶上去的插件实例，可换可顶。**

## 2. 决定

### 2.1 什么是插件、什么不是

| 位置 | 是不是插件 | 为什么 |
|---|---|---|
| 出声（演奏者：小月相 / 元音版 / SoundFont / 人类录音 / 以后上传的 AI 歌手） | **插件** `performer` | 开放集：谁都可能加一种 |
| 效果器（eq / comp / reverb / delay / chorus / gain…） | **插件** `fx` | 开放集；10-10 user 已拍「每一格写插件 id + 版本号；认不出的原样留着、引擎跳过、混音台画灰」 |
| 文件进出（MusicXML 进出、mp3 出、PDF 出、以后 MIDI…） | **插件** `file` | 开放集。`.mxl` 容器本身（`.moonsinger/` 目录 + 各份 JSON 的契约）是核心，不是插件 |
| 音源来源（家族音源库 / 本机文件 / OneDrive 自己的文件夹） | **插件** `source` | 开放集；反弃坑（ADR-0006 ③）本来就要能换 |
| 显示（五线谱 / 简谱 / 钢琴卷帘） | **库**，不是插件 | user：「可以枚举」——是刀⑤的几个实现，接口留位，不走注册表 |
| 键盘（音 / 符 / 词 / 以后和弦） | **前端库**，不是插件 | user 10-14「键盘只管交互状态机，它不懂音乐」；见 `../20261014-editing-mental-model.md` §2 |
| 乐谱数据模型 / 时间线（谱 → 秒）/ 录音房（混音 + 走带）/ 指令引擎 / 键盘库 | **核心** | 它们是宿主，插件挂在它们身上 |

### 2.2 身份与地址

- 每个插件一个**内部 guid**（出生时生成，永不改）+ 一个**英文名**（人读的、稳定的，故障恢复用）+ **版本号**（整数）。地址写成 `种类:名字@版本`（如 `performer:tsukuyomi@1`、`fx:eq@1`、`file:musicxml@1`），guid 是真身份、地址是人看的。
- 歌里（`.moonsinger/*.json`）存：`{ guid, kind, name, version, params }`——**地址 + by-value 参数，不存代码**。小月相的模型包 sha256 是**参数**不是地址（换模型包 = 同一个插件换参数）。
- 解析（打开歌 / 上场时）：
  1. 按 guid 找到、版本一样 → 直接用。
  2. 按 guid 找到、app 里的版本更新 → **画灰 + 提示「升级到 @N？」**，user 点了才跑这个插件自带的迁移函数（点之前灰、不出声、不自动改——user「插件升级应该能提示然后点了自愈。点之前灰」）。
  3. guid 找不到、同种类里有同英文名的 → 画灰 + 提示「用 X 顶上？」，人确认才换（这就是英文名的用途：故障恢复要人干预）。
  4. 都没有 → 原样带着、画灰、不出声、不替补（现有纪律，10-07「不是显示自动上，而是就是不出声，报错，人类手动换」）。

#### 2.2 补议（2026-10-14 晚，**待 user 拍**；Claude Fable 5.1 记）

user 原话（刀 1 进行中，顺着「点之前灰」往下想）：
- 「插件升级了是变灰提示你按升级，而不是静默换。」
- 「然后不要弹十几个窗，而是在轨道上面有提示吧 / 不过这样是不是不大好，因为你不会看到全部的轨道。所以还是静默？或者patch和minor静默。major的时候打开的时候提示全部？然后找不到插件也是这个窗口。然后如果是旧app打开怎么办？我们需要anti abandonware」
- 「就是大曲子你灰了不知道的话导出发社交媒体没检查就搞笑了。导出的时候也应该护栏一下。play是否需要护栏？但是一直弹窗很烦」

现状（as-of v0.12.0）：每次按播放 / 导出都走 `prepare()`，有声部出不了声 = 每次弹一条 toast（`main.ts` 「这些声部没有出声，其余照放」）；没有常驻角标，导出面板不列。

AI 建议（一套机制四个出口；不改上面 §2.2 的四种解析情况，只定「怎么露出来」）：
1. **一张清单**：开歌 / 换人 / 升级后把所有「这位有事」的声部收成一张表（等升级 / 同名顶上要确认 / 认不出 / 找不到声音）。出口 = ① 谱上名字灰 + 角标，歌手牌里写为什么 + 该按的钮；② 走带 |▶ 右上角常驻角标「N 不出声」（同「循环」角标位），点它开清单；③ 开歌一条 toast「N 位演奏者需要看一眼」，点 toast 开清单。不自动弹、不模态、不逐轨弹。
2. **patch / minor / major 落在迁移步骤上**，文件里仍是一个整数版本：代码修了形状没变 = 不 bump（什么都不发生）；版本 +1 且迁移无损 = 步骤标 `quiet`（内存里静默迁、下次存按新形状写）；迁移会改出声或丢东西 = 步骤标 `ask`（进清单、灰、不出声、点了才迁）。
3. **导出护栏**：导出面板里一行列出不出声的轨，主按钮改字「照样导出」；不拦（10-08「不警察用户」）。
4. **play**：角标常驻，toast 只在清单变了时说一次，之后不弹。
5. **旧 app 开新歌**：插件版本比 app 新 = 歌照开、那条轨灰 + 「这位是 @N，这个 app 只认到 @M：更新 app 或换人顶上」、字节原样带着、存回不降级（宿主只认 guid / kind / name / version 路由，params 不透明）。容器层 `project.ts newer()` 的整首拒开不动（那是格式宪法）。不做「旧 app 拿新参数尽量用」（= 自动替补）。
6. 代价：quiet 迁移存回后旧 app 看到新版本 → 那条轨灰；和容器版本今天的行为一致。替代 = 插件参数永不 bump、只加可选字段。

### 2.3 谱上的身份 vs 台上的插件

- **谱上记乐理的 role**（二胡 / Q726306 这类概念 id 束 + 名字，by value），这是人读谱时的身份；二胡用 GS Violin 顶，谱上还是二胡、台上标「顶」。
- **轨绑的是插件实例**（地址 + 参数）。出声那条路只认插件实例；role / 乐器概念是元数据，承重的只有一点点：给目录、记谱默认（谱号 / 八度 / 连断的底色）用，不参与出声（user「这么说它还是承重了一点点的」）。
- ⑦ 两个方案 → **方案 2（乐器为主，再对齐插件）**；现有休息室（角色 + 候选）的分法不推倒，演奏者那一层套统一的插件壳。
- 人类录音 = `performer:recording`：输出和小月相一样是「块」进录音房，录的字节 by value 进 `.mxl`（像嵌的 sf2），对齐 / 延迟补偿是它自己的参数。录音纪元不另开一条路。

### 2.4 「没有 builtin」的含义

小月相的代码照 vendor 在 app 里发（硬规则 #8：语音不离设备，引擎随 app），但在系统里**只是注册表里的一项**：胶水 / 时间线 / 录音房 / 界面里不许再出现 `if (engine === "tsukuyomi" | "soundfont" | "vowel-sampler")`（as-of 2026-10-14：main.ts 28 处、timeline.ts 4 处、project.ts 3 处、perform.ts 1 处），一律问注册表「这个地址谁认领、它能什么」。新歌默认演奏者 = 小月相由一张**预设表**给（数据），不是代码特判。

### 2.5 歌手管理的界面（方向，user「你也可以pushback说就照着水果 cubase做」→ 照 Cubase 的 inspector，不照水果）

一张卡三段，点谱前面的名字就开：① 身份（乐理 role + 谱上怎么写）；② **插件槽**（谁在演 `GS Violin ▾ 顶`，点 = 开浏览器 = 现在的找人视图；槽旁的参数行由插件自报，不是 main.ts 写死）；③ 混音（静 / 独 / 推子 / 出到，和混音台卡片同一份）。乐器页并进这张卡；混音台卡片顶上放同一个插件槽。不照搬的：多窗口 / 模态插件窗；键盘 / 谱 / 底座的格局不动（「Nokia 彩铃编辑器不是 DAW」照旧）。界面本身是另一刀，不在本 ADR 里定细节。

### 2.6 换人不锁；跟人 / 跟轨两张清单；换完提示不拦（2026-10-14 user「我们一开始的设计是role可以换轻音少女。但是后来实践中确实还是混音之后role绑的插件确实需要锁死吗？我当时说的我讨厌daw的东西还是逃不掉吗？」→ AI 答「不用锁」，user「嗯」）

- user 讨厌的 DAW 东西 = **外链依赖**（工程记的是「某个插件在某台机器上」，插件不在 = 工程废）。解法 = by value + 认不出画灰不出声 + 点了才自愈（§2.2），和锁不锁无关；锁死反而更像 DAW。
- 混音后换人的代价是真的，但靠分清**什么跟人、什么跟轨**（v0.9.9 已经这么分，这里说透）：
  - **跟人走**（换人一起换）：响度校准 `calibrationDb`、演奏者自己的链 `CandidateV2.chain`（琴箱 / 音箱 / 歌手自带的底色）、力度表、记号解读、连断底色、修八度、分段唱、着力点、出声方式（块 / 音符表）。
  - **跟轨走**（换人留着）：推子、声像、通道链（EQ / 压缩）、发送、出到、静音 / 独奏。
  - 跟谱走：音、歌词、记号、乐理 role / 乐器概念、谱号；休息室里别的候选留着（下线不删）。
- 换完的那一刻**提示一句、不拦**：「这条轨的 EQ / 压缩是给 X 调的——重置成默认 / 留着 / 搬进演奏者链」，人选。「换轻音少女」= 乐队预设换一整套演奏者（role 不动），混音留着，哪条轨不对再调。
- as-of 2026-10-14 代码核过：换人只翻 `r.active`，随之动的 = 校准进通道、时间线重算（出声方式 / 力度表 / 记号解读 / gapSec / 修八度 / 分段 / 着力点）、演奏者链、SoundFont 子集进录音房、谱面重画（× 符头 / 不认的记号灰 / 歌词灰 / 叠音灰 / 鼓谱 / 合租谱号）、pad 提示、撤销一步；月读的块缓存键不含演奏者（换回来不重唱）；不动的 = 轨的推子 / 声像 / 通道链 / 发送 / 出到 / 静音独奏、谱、别的候选。缺的只是那句提示。

## 3. 否决的（别再提）

- 小月相「内置、不是插件」（本仓 CLAUDE.md 2026-10-05 那条）：**吃书**。第一公民的地位不变（默认演奏者、UX 为她服务），但在代码里她只是注册表里一项。
- 显示 / 键盘做成插件：否（可枚举 = 库）。
- 用内容哈希当插件身份（user 自己的「hash id」）：否，改 guid + 英文名 + 版本（家族早有「内容哈希身份否决」）。
- 自动迁移 / 自动替补：否（点了才自愈，点之前灰）。

## 4. 对后面几刀的约束

- **刀 1（抽唱歌 / 播放胶水）同时建注册表** `src/performers/`（`registry.ts` + `tsukuyomi.ts` / `vowel-sampler.ts` / `soundfont.ts` 三个 adapter），接口 = 这个插件能什么（块还是音符表 / 能不能叠音 / 唱不唱字 / 音域提示）+ 准备（库进录音房 / 元音表 / 引擎预热）+ 出声参数（PerformerInfo 那一份）+ 署名 + 乐器页的参数行；胶水里按引擎名的分支归零。文件 / 效果器 / 来源三类注册表在各自的那一刀建，形状同一个壳。
- 契约（`src/format/contract.ts` + `../20261007-data-contract-draft.md`）加统一的插件壳 `{ guid, kind, name, version, params }`；现有 `CandidateV2.instrument`（按引擎分的判别联合）= 第一版 `params`，迁移时套壳，不改字段。版本号 / 迁移 / 冻结样本按格式红线的规矩。
- 测试：注册表的解析规则（2.2 四种情况）单元测；三个 adapter 各一份「表说能什么 = 真能什么」（同 `test/honors.test.ts` 的精神）。
