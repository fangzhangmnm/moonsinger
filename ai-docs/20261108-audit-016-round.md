# 0.16 这一轮（itch v0.15.4 → v0.16.23）的架构审计

> created 20261108 by Claude Fable 5.1 · as-of v0.16.23 / 2026-11-08
> user 11-08：「你是 fable 了，帮我看一下修一下键盘的性能，修好之后 audit 一下 opus 的一大堆工作，看架构风险。」
> 范围：itch 上那版（v0.15.4，02a1c95）到今天推上开发版的 v0.16.23（fa9ca64），31 个版本，加上工作区里还没提交的三处半成品。
> 读法：**先看「一句话」和「风险分级」两节**；后面是每一层的细账。事实和我的判断分开写，判断处标〔判断〕。

## 0. 一句话

这一轮没有碰同步 / 格式 / 出声这三条红线的本体，纪律守住了；**真正的架构风险在「谱面上长出来的编辑器控件」和「主程序里一张一张手糊的面板」**——都是量的积累，还没出事故，但再长一轮就会。另外查出一条**真漏**（试听过的音色库永不释放，已在 v0.16.23 修）和一条**假警报**（sync 测试两条红是测试撞上新控件，不是丢字节，已修测试）。

## 1. 先说键盘延迟（今天的起因）

事实（都是今天量 / 核出来的）：

- 同一台 iPad：itch 版（在浏览器标签里）快；开发版装成 PWA 慢；Edge 里新开一页开同一个开发版，快；重装 PWA，照旧慢；PC 上同一版快。→ **不是版本回归**，是「独立窗 vs 标签页」两条声音通路的差别（iPadOS 上从 Edge 装的 PWA 跑在 Edge 自己的容器里）。
- 无头 Chromium 里量即兴那条路（按下 → 把音交给声音线程）：正常 CPU 中位 2 ms，压慢四倍 5–8 ms，换上 GS 乐器最差 38 ms。
- iPad 的 WebKit 报给网页的「输出延迟」永远是 0，所以 app 看不见那块缓冲有多大。
- 10-17 / 10-21 立的三条纪律——先响后写、重画合并到下一帧、排版和存档编码在 worker——0.16 没有推翻：itch 版到现在，键盘 → 宿主 → 出声这条路只改了几行（叠音高亮、音域键、图标）。
- 〔判断〕这件事和 F-219「切后台后声音比高亮慢一拍」很可能同源：都是那份常驻的独立窗进程里声音上下文和系统对不上。

做了：**手感探针**（v0.16.23）——app 自己量「手指按下 → 主线程接到 → 交给声音线程」三段，加主线程最长停顿和音频时钟一步跳多大（系统给的声音块，瞒不了）；超标才在键盘上沿露一行数字（带「最慢一步」的名字）+ 进黑匣子；点一下这次打开不再显示。你什么都不用做，下次再慢它自己说是哪一层。

## 2. 风险分级

### 高（会出事故的那种）

**没有。** 格式只加了可选字段、守卫全绿；同步代码没动；出声引擎没动。

### 中（结构性的，再长一轮就难收）

1. **排版器在吸收编辑器的控件**。眼睛 / 喇叭两颗钮、每段底下的虚线框、曲段的「⋯」、「1=C」淡提示、和弦级数、「按 C 调看」——这一轮全做成了排版器的选项：每加一样 = 排版器里多一段画图元 + 多一张点击框表 + Layout 多一个字段 + 过 worker 边界多一份数据 + 谱面手势多一个分支 + PDF 多一处要减掉。eye / 喇叭那两颗钮还把名字那一栏的最小宽度顶到了钮的宽度（屏幕和 PDF 同一条规矩，版面才不漂）。〔判断〕再这样加两轮，排版器就不再是「谱 → 版面」的纯函数，而是编辑器的后半截；PDF 所见即所得靠「每样都记得减掉」维持。**这是「五线谱显示思路」那份设计要正面回答的事**（另一份文档）。
2. **主程序（main.ts）又长了 600 行，新面板全是手糊的**：声部管理、加声部小菜单、曲段菜单、小卡三颗钮，都是「HTML 字串 + data-v 点击分发 + 各自的关闭逻辑」。例子：加声部小菜单自己写了一套「点外面关掉」（setTimeout 挂 pointerdown），和现成的小菜单组件不是一套。谱头面板倒是单独抽成了文件（header-panel.ts），说明 Opus 知道该怎么做，只是赶活时没每次都做。〔判断〕风险不在某一处，在「下一个面板又糊在 main.ts」成了默认；设置分页那一轮（你点了名的）是收口的时机：面板进 `src/app/panels/`，共用一个「面板 / 小菜单」底座。
3. **谱面手势是一条按位置排的 if 链**。score-view 的 `tap()` 里新加的东西要插在固定位置，注释都成了「0⁻、0、0⅛⁻、0½」这种分数编号；长按 / 右键又各走一条平行的路（两颗钮的「松手才算点」`tgDown` 在三处分别判）。这是 F-17 第 3 期（手势状态机）早就记了的债，这一轮把它压得更深。Opus 自己就在这里踩过一次（鼠标长按两颗钮不触发）。
4. **「按 C 调看」在两处实现**：排版器里整首换算一次，谱面手势里鬼音符 / 拖音高又各自换算回去。两面镜子必须永远一致；原来的调（`realFifths`）是塞在调号 token 上的一个显示用字段。〔判断〕现在量小、能接受；正确形状是一层「显示变换 + 反查」，排版和手势都只问它。

### 低（记一笔就行）

5. **格式**：候选多了 `castAs`（上场时当的是哪件乐器）、视图态多了 `finder`（目录翻到哪），都是可选字段，形状快照更新了，旧 app 原样写回。没拨 minor 拍子——按 10-21 的三级拍子，老 app 缺这个功能该提示一次；这两个字段是显示 / 记忆性质，不提示也不丢东西。
6. **时间线允许音在 0 之前开始**（歌开头的琶音低音先滚）。时间线自己从最早的音起算；别的消费者（循环、定位、离线导出）这一轮 E2E 都绿。
7. **设备设置散成四个独立的键**（按 C 调看、和弦级数、混音台排数、即兴目录翻到哪），各自在 main.ts 里解析。设置分页时顺手收成一个带类型的设备设置模块。
8. **工作区里的三处半成品**（键盘音域「拉 + 对账」、换 GS 乐器一步撤销、两颗钮上移缩小）方向都对：音域跟随用「身份键变了就对一次账」取代到处记得推，正是 10-04 家规说的解耦；换乐器一步提交修的是撤销契约的真 bug（原来三步、撤一下撤不回、声音没到先改了名字）。差的是：两颗钮缩小后一条 E2E 的尺寸门槛要跟着改，新测试文件还没登记进分区表。

## 3. 真漏一条（已修）

**试听过的音色库永不释放**。目录里每点一件乐器 = 那件的音色库在**音频线程**里解析一遍、再开一个专用合成器、主线程还留一份字节；整个 app 从 10 月到现在没有任何地方调过「卸掉」。0.16 把「换乐器」做成直进目录，逛一下午就是几十份、几百 MB 只涨不落，iPad 独立窗的内存上限又比标签低。v0.16.23：试听过的最近三件留着（你说的「快速来回比」），歌里任何候选用着的永不卸，关目录全卸，卸了再点自动重载。E2E 守着（点四件只剩三份；关目录归零；上场的一直在）。
〔判断〕更稳的形状是「谁用着就留、没人用就卸」的对账——从休息室候选 ∪ 试听台 ∪ 正在放的时间线推出想要的集合，每次变化和声音线程里实际装着的比一遍——而不是各处手动 trim。记在任务单。

## 4. 假警报一条（已修测试）

整套 E2E 88/89，`sync` 第 ⑦ 步「三路同时推：零冲突、云端跟着」云端少最新一个音、⑧ 跟着红，单跑也红，**在改之前的 v0.16.22 构建上同样红**。回溯：v0.15.7 绿、v0.16.13 绿、v0.16.19 绿、**v0.16.20 起红**。真相：测试放光标是盲点屏幕上 (300, 300)；v0.16.20 起每段底下有「＋ 声部」虚线框，歌一长到折成两行，框正好压在那一点上——点中 = 开菜单，后面打的音进不了谱，云端自然少一个。不是同步丢字节。测试改成按排版点第一行五线谱右端，43/43。
〔判断〕这条暴露的流程问题比 bug 本身重要：三个版本的整套 E2E 都带着它红，被「并行红、单跑绿 = 负载抖动」的规矩放过去了。**红了必须单跑，单跑还红就不许发版**——这条规矩在，执行没跟上。

## 5. 每一层的细账

- **格式红线区**（`src/format/`）：只加可选字段（候选 `castAs`、视图态 `finder`），`shape.json` 已更新；`withCastAs` / `candidateJson` 两个纯函数；迁移链没动。✔
- **谱数据层**（`src/score/`）：新纯函数 `headerSpot / headerVals / setHeaderAt`（谱头一处的读改，改调号时按新调号重拼、改开头速度写齐每一行，值没变不多记一步撤销），改调号重拼是整个替换 token、不原地改（撤销快照安全）；`inputAuto` 跟谱 / 手动；3/8 拍符杠分组修正；`addPaper` 多了「插在前面」。✔
- **排版器**（`src/render/engrave.ts`，+290 行）：见风险 1。好的一面：和弦级数的计算放在排版器里 = 在 worker 里，没回主线程；「按 C 调看」在排版前换算、谱号仍按实际音挑（换看法谱号不跳）。
- **谱面手势**（`src/ui/score-view.ts`，+191 行）：见风险 3、4。谱头放宽的碰撞箱「按下不抢、没拖才算点」做得对（框选不受影响）。
- **主程序**（`src/app/main.ts`，+575 行 → 3926 行）：见风险 2。`castAsOf` 点回旧候选时按目录反查，不按引擎名分支（守住 ADR-0004）。✔
- **目录**（`src/ui/finder.ts`）：两份记忆（歌里 / 即兴）各记各的；「这首歌的乐器预设」一排。结构合理。
- **键盘 / 出声**：只改了几行（叠音高亮、音域键、图标）。纪律守住。
- **测试**：单测 972 → 1019；E2E 整套 88/89 → 修测试后应为 89/89（整套没重跑，sync 单跑绿）；新加 `feel-probe`（6）、`audition-banks`（9）。

## 6. 建议的顺序（给你拍）

1. **先不再往 main.ts 里糊面板**：设置分页那一轮一起立规矩（面板进 `src/app/panels/`，共用一个底座）。
2. **五线谱显示思路**那份设计里把「排版器只排可印的谱、编辑器控件是另一层」定下来，再决定两颗钮 / 虚线框 / 级数标签各归哪一层。排谱三刀（记号不撑开音距、纵向贴着摆、密音压紧）等这个定了再做，不然两边打架。
3. 工作区那三处半成品：改一条测试门槛、登记一个测试文件，就能推。
4. 音色库的对账式生命周期、「弹」模式先响再提交——小活，顺手。
