# 把隐藏的东西清掉：方案（先减，后加）

> created 2026-11-12 by Claude Fable 5.2（MoonSinger 统筹）· as-of v0.17.8 / 2026-11-12
> 依据：家族根 `CLAUDE.md` 硬规则 #9「文件就是语义」；全表 `ai-docs/20261112-silent-conversions-full-table.md`（施工的会话逐处核的，下面的编号是它的）。
> **这是给 user 看的方案，没批之前一处不动。** 每一条标了是减还是加。顺序 = 能删就删；删不了的并成一个；再不行才写进文件；最后才是加机制。
> user 的话（同一晚）：「我觉得这几轮修都是减东西，而不是加东西」「我真的没法接受这些 if else」「保证不会发生改变的是这个谱子」。

## 〇、修订（同一晚，user 看过第一稿之后）——以这一节为准，和下面冲突的地方照它

user 的话：

- 「我们以后调默认值的时候，就相当于调写到新文件里的值…我们的引擎里没有常数量。…当然也不用那么极端，我说的是理想情况。」
- 「如果没有转换的话，那对话框也就不要…六个对话框确实没法接受，我最讨厌的就是说，我这个一辈子每多一次改动都会多一轮这个转换，最后一个长长的转换算法…所以说尽量就说文件上怎么写我们就怎么弄…就相当于我们文件是永生的。」「如果不转换，你整个算法都读不了的时候才是。」
- 「小月像的那个…你也都暴露出来。」「（自己定一个归一化机制）虽然物理上是很容易定的，但反而把别人调的东西全全调乱了。」

照这个，方案改四处：

1. **默认值住在「新文件的模板」里。** 模板 = 一份和歌同样格式的数据（一位出厂的小月相、一位出厂的 SoundFont 乐手、一条出厂的轨、一条出厂的总轨…）。新建 = 按值抄模板。引擎只吃明写的数，自己不带默认。老文件里缺的数只在读文件那一处用现行模板补，存的时候写下来。——第三节照旧；第四节那六样数就是写进模板、再随新建抄进文件；全表 3-1、3-2 那十几组散着的「没写就当」并成读文件那一处的一次补全。
2. **不要转换，也就不要对话框。** 第五节里「升级链留下来的步骤弹对话框」改成：今天加的那两步**不需要了**——老文件里没有的新东西（乐器概念、小月相的力度深度）用模板补或者照文件里有的显示；老文件里有而新版不用的东西（老乐手的力度 dB 表）原样留着、不删。十月头几天那四步（形状完全不同的第 1 版）：先只读地扫歌库，一首都没有就删；有，才是全软件唯一的一个对话框。第六节第 1 件随之作废。
3. **归一化只在没有作者意图的地方定**：小月相的块乘多少（约 2.12）= 她自己的归一化，写进文件、乐器页上能看能调。乐器库里各件乐器之间的轻重是库作者调的，不碰。不做「按物理量把每件拉齐」。
4. **还没想清的一处，单独写给 user**：老歌里小月相身上那张旧的力度 dB 表。新版今天上午起不用它了（改成力度表 × 深度）。照「文件上怎么写就怎么读」，是让它算数（老歌里她的强弱照那张表），还是当退役的键留着不理（老歌里她的强弱照现行的规矩）。两种对老歌的声音不一样。user 点头前不动。

第八节「这个方案自己加了什么」随之变成：对话框 0 个（最多 1 个）；文件里多六样数；一份模板（它替掉散在各处的默认表，不是新增的机制）。

## 三、存的时候都明写出来（减掉「只写不是默认的」）

- 全表第四节那 19 个键：现在是「等于默认就不写」。改成每次都写。写的那一侧少 19 个判断。
- 老乐手身上缺的那些数（3-1 一整组：力度表、演奏法 17 个数、分段唱、唱法旋钮、缝…）：存的时候按现行默认补全写出去。读的那一侧照旧「没写 = 现行默认」。
- 这就是 user 说的「没写可以用现行默认，但之后就得写下来」。打开不改文件，人存的时候才写。
- 代价：一批「老歌存出来一个字节不变」的测试会红。它们守的正是「和以前一样」，重冻。

## 五、要说出来的（用现有的通道，不新造机制）

开文件本来就会交回一串「要告诉人的话」（现在只有别家的谱在用）。下面这些都往它里面放，不另做一套：

- 升级链里**留下来的**步骤（今天加的两步每首老歌都要过：删掉老乐手的力度 dB 表；老预设名换成乐器概念）：改成**弹对话框、逐条说明、人点了才做**。这是硬规则 #9 原文要求的那一个对话框，全软件只有这一个。
- 老文件里带着的 mp3 存的时候不再带（2-21）：列进同一个对话框。
- 别家的谱没写速度按 ♩=90、没写调号按 C、没写拍号按 4/4（2-11）：列进导入的那份报告。
- 合租关系不合法、两个声部共用一位乐手（2-6、2-14）：照实说，内存里凑合着开，不往文件里改。

## 六、要 user 定的（四件）

1. **升级链留下来的那两步**：照上面「弹对话框才做」；还是连这两步也不要——那样今天之前存的歌，乐手那一份全读不了，谱子照常打开、每个声部要重新选乐器。统筹建议前者。
2. **老 mp3**：存的时候不再带（现在的做法，说一声）；还是原样留在文件里不动。
3. **哼的字**存在歌上还是每位乐手身上。
4. **「原声」没写**算 1（参数表写的）还是 1 − 湿（程序实际做的）。两种听起来不一样，要听。

## 七、不动的，和为什么

- 音的编号整首重编（2-7）：编号只在那一份文件里有用，不是语义。
- 乐器的谱上叫法存的时候换成现行目录的（2-20）：它是从乐器的身份查出来的派生的字，和压平的那份谱一样每次存都重出。
- 弱引用没带来 = 没人上场（2-17）、打开更新版本写的歌说一次（2-18）、别家谱读不了的记号数出来（2-15）：本来就是明说的。
- 声像正中每边 −3 dB（5-5）：算理想那一层。两边合起来的功率不变，没有改增益的意思。
- 自动谱号、自动八度线的门槛数（5-14）：理想那一层，只影响画面。
- 理想那一层的算法（怎么唱、怎么合成、效果器公式）：不动；第四节加的版本号让人找得回是哪一版程序。

## 八、这个方案自己加了什么（如实数）

- 一个对话框（硬规则 #9 要的那一个）。
- 文件里多六样数。
- 没有登记表、没有新的测试机制、没有改动清单——统筹之前提的那几样先都不做；删完、并完之后还剩多少隐藏的，再看用不用得上。

## 九、顺序（每一步单独一版）

第 14 条（已放行）→ 一、二两节 → 三 → 四 → 五。第六节的四件 user 定了再做对应的那一处。
