## 一、规矩（1 + 1）

1. **分工。** 小弟：侦察、实现、测试、守卫、文档（流程图 `20261109-pipelines.md` 跟改动同一个提交更新；仓 `CLAUDE.md` 的流水）、发开发版。统筹：这份施工单、ADR、设计稿；审 1a 的切线表和第三刀；回答第五节的问题。统筹不写代码，小弟不做设计决定。
2. **什么时候停下来问**（写在第五节，再给统筹发一条消息）：
   - 施工单和设计稿没写，而且答案会动到这四样之一：设计稿第 3.1 节的「谁不许知道什么」；歌的文件格式；点击 / 光标指向谱的地址；user 看得见的行为。
   - 守卫过不了、想放宽守卫。
   - 活比工单表写的大出一倍。
   - 别的（命名、文件怎么拆、内部数据结构、测试怎么写）自己定，在施工记录里记一行。
3. **接口形状。** 设计稿第 7 节是提案。字段名、参数形状可以自己调，调完回写第 7 节、施工记录里记一句。「谁不许知道什么」不能自己动。
4. **提交。** 两个会话共用这个目录：各自只提交自己改的文件，写明路径，不用 `git add -A`。这份施工单里，小弟写第五节的「问」、第六节、工单表的状态列；别的地方统筹写。
5. **测试和发版**照仓 `CLAUDE.md` 的分档；开发版照常发；正式版不碰；版本号一律 patch。
6. **消息。** 一刀做完、或者有事要问：先写进文件，再给统筹发一条消息（一句话 + 看哪一节）。每刀做完把要记的都写进文件再停，这样两边随时可以压缩或重开。
7. **不拿「改动小」当理由**（家规）。想加一个施工单没写的口子时，先答两句：它以后会长成什么；它反映了什么结构。答不出来就写进第五节问。

## 三、每刀要点

### 1a 侦察（先做这个）

交一份文件 `ai-docs/<当天日期>-engrave-cut-map.md`，里面八样：

1. `engrave()`（`src/render/engrave.ts` 第 406–1730 行）的函数体按行号分段：每段做什么 → 归设计稿第 3.3 节六步里的哪一步（预处理 / 谱种的表 / 量 / 排 / 画 / 叠），标成「公共框架」「五线谱的行」「两样搅在一起」。
2. 搅在一起的地方：哪些局部变量被跨段读写，打算怎么拆。这是切的难点，写具体。
3. `Layout` 的字段逐个标：和谱种无关 / 五线谱专属 / 混着。设计稿第 2.2 节点过几个（`yOf` / `dOf`、`HitNote.d`、`CaretHead.shift`、`SystemBox.staffTop` / `staff`、clefs、keyHints、sharedRows / virtual），核实并补全。
4. `src/ui/score-view.ts` 和 `src/export/score-pdf.ts` 里读五线谱专属字段的位置清单（第二刀用）。
5. 仓里已有的冻结版面（`scripts/freeze-layout.mjs`、`scripts/layout-local-diff.mjs`、`test/fixtures`）能不能直接当守卫 3（分家前后图元逐个相同）：盖到了哪些样本歌，比到什么粒度，缺什么。
6. 量一个数：worker 每次把整首歌拷过去，占一次排版（大歌约 28 毫秒）的多少。只报数字，不做优化（设计稿第 3.10 节：占得少就不做「只送变了的轨」）。
7. 建议的切法：分几个提交、先后顺序。要求每个提交之后守卫 3 都是绿的。
8. 设计稿第 3.3 节的「量 → 排 → 画」套在五线谱现在的排法上，哪里套不上。

探针脚本放 job 的临时目录，不进仓。
