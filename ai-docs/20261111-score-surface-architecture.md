## 1. 一页看完

**结论**

1. 任务书把五线谱、简谱、tracker、钢琴格、三岁档并排叫「显示引擎」，当成同一种东西热插拔。它们其实是三种不同的东西，要三个不同的接口：
   - **同一份谱换画法**：五线谱、简谱、字母简谱、三岁档。都排在纸上、分行分页、能印。换的只是「一行怎么画」。
   - **换一整块谱面，写法也换**：tracker、重新发明的钢琴格（串珠）。不分页，手指点到的是一个时刻，不是两个音之间。
   - **换数据**：真正的钢琴格（音能重叠、每个音自己的力度）。这是数据模型的事，不是显示的事，要改 ADR-0004，归 user 以后定。
2. 能热插拔的最小单位是**一行的画法**，不是一整页的引擎。一首歌里本来就有好几种行（五线谱、鼓的一线谱、隐藏声部的细行、简谱的 X 行）。纸、分行分页、歌词、间距是一个共用的框架，由它来调各种行的画法。
3. **横向 = 时间，归共用的间距模块；纵向的意思归各种画法。** 「这个横坐标是哪个时刻」只算一遍，所有谱都用。「这个高度是哪个音」只有五线谱和钢琴格有，简谱和 tracker 没有。
4. **写法归核心，不归谱面，也不归键盘，而且只有一种**（修订 1）：写一个音，谁都不挪别人——换掉正对着的那个，撞到下一个音就停。推和拉是在改时间的结构，是明着的动作，归小节线菜单和选区。所有谱面（纸面、tracker、钢琴格）用同一条。
5. **键盘不认谱面，谱面不认键盘。** 键盘只说「哪个键按下了」；一层「输入法」把键翻译成指令；核心执行。显示和键盘共用的知识（音怎么读成简谱音级、每个记号叫什么 / 画成什么 / 点一下怎么说明）各放进一张共用的表，两边都只读表。

## 2. 对 Opus 两份稿的审查

### 2.1 留下的

- 五线谱 / 简谱 / 字母是同一份数据换画法，之间无损；格子那一家和 token 之间只能单向（纪要 §20）。这是整个设计的地基，我沿用。
- 「全量、不静默」；间距用现成的 `spacing.ts`（弹簧 + 顶杆）；左边挂的东西当顶杆；排版参数做成一张表。
- 拿团子人声和 Once upon a Tale 对标，验收项「bongo 每小节八分等距」。

### 2.2 架构上不同意的（任务书）

1. **单位错了。** 任务书第 3 节第 1 条要「五线谱、简谱、tracker、钢琴格、三岁档都能热插拔」的一个接口，输入是歌、输出是版面数据。一个接口装五样东西，要么宽到没有意义，要么把 tracker 和钢琴格硬塞进「分行分页的版面」。见第 1 节结论 1。
2. **「版面数据大部分和谱种无关，五线谱专属的只有 yOf / dOf」低估了。** 代码里五线谱的东西还有：
   - 版面数据里：音的点击框带「在第几条线上」（`HitNote.d`）；光标落点带「谱号 / 八度线位移」（`CaretHead.shift`）；每一行带「五线谱顶线在哪、是大谱表的上还是下」（`SystemBox.staffTop / staff`）；谱号的点击框；调号处的「1=C」提示；合租并成一行（`sharedRows / virtual`，简谱里不并）。
   - 谱面视图里（`score-view.ts`，1522 行）：光标画成一根从谱上方到谱下方的竖线；鬼音符带加线；选区带从谱顶画到歌词；拖音高按「半个线间距 = 一级」算。
   - 所以要切的不只是两个函数，是「纵向的意思」整个搬进行的画法里，连同光标长什么样、鬼音符长什么样、竖着拖是什么意思。
3. **「手势怎么映射回 token」把地址钉死在「第几个 token」上。** 鼓格子（在休止里面放光标，鼓设计稿 R2）、tracker、播放高亮、听模式的「从这儿放」要的都是时刻。现有代码已经在往时刻长：`EditorState.lead`（光标在尾巴后面多少 tick）、听模式菜单带 `tick`。接口里要有时刻，而且只算一遍（第 3.4 节）。
4. **没说写法归谁。** 推着写还是盖着写如果留在各个谱面里，每做一种格子就要重写一遍编辑语义。user 怕的「奇怪的锁定，拖不动」（纪要 §30）就是从这里长出来的。
5. **键盘没出现。** 任务书只管显示，这没错；但简谱显示和键盘其实共用两样知识，现在各有各的一份：
   - 音怎么读成简谱音级（1–7、升降、八度点）：小键盘的键面上有一份（`PadCell`），剪贴板的简谱文字有一份（`clipboard.ts`）。简谱画法再写一份就是第三份。
   - 记号画成什么：小键盘的符号层自己画了一套力度字形、发夹、连线（`pad.ts` 里的 `DYN_CELL`、`SWELL_CELL` 等）。下一轮设计「尊老爱幼模式下怎么输入这些记号」时，键面要跟着谱种换字，没有共用的表就没法换。
6. **公共模块只列了名单，没说谁调谁。** 「间距、断行分页、歌词让路、天际线……做成共用的深模块」如果做成一个工具箱，每种谱还是要自己写一遍版面家具（歌名、作者栏、曲段名、声部名、细行、页框）、分页、歌词，只是共用几个小函数。现在 `engrave()` 一个函数约 1300 行，加一种谱 = 再抄一个。要反过来：一个框架调各种行的画法（第 3.3 节）。
7. **第一刀「单声部简谱 + 开关」没有先切接口。** 照做会长成第二个整页引擎，两个引擎各有一份版面家具，以后每加一个版面功能做两遍。
8. 小的：任务书第 4 节还写着「14 件等 user」，同一份的 3½ 节和 UX 稿都说全部拍完了。施工的人读到会去问一遍。我在任务书顶上加了指路。

### 2.3 UX 稿里会卡住架构的几处

UX 稿的画法不重审，只列和架构有关的：

1. 「设置全部跟歌走」，但「力度用字跟界面语言」。同一首歌在中文和英文设备上印出来不一样。这是 user 拍的，不改；但排版的输入里要明着带「语言」，画法不许自己去读界面语言（排版在 worker 里跑，测试也要同样输入同样输出）。
2. 「谱种整首一个」和「鼓 = X 行、隐藏 = 细行」放在一起看：一首简谱歌里至少三种行。所以谱种不是「一个引擎」，是一张表：哪种声部用哪种行的画法（第 3.3 节）。
3. 「全量」只有原则，没有判据。判据见第 3.9 节。
4. 「每轨的和弦选项分档归 Fable」：第 3.7 节给了。
5. 「显示设置归歌以后，锁着时切它怎么办」：修改锁里现成有答案，第 3.7 节。
6. UX 稿没说简谱下还能不能打字。按这份架构，输入和谱种无关，所以简谱第一天就能用现在的键盘写；只有「竖着拖改音高」简谱没有。要不要先做成只读，见第 8 节。
7. 6/8 的下划线分组还标着「AI 记忆，没核」。不是架构问题，施工前要核。

## 3. 架构

### 3.1 谁知道什么（归属表）

| 模块 | 知道 | 不许知道 | 对外只说 |
|---|---|---|---|
| 键盘（前端库） | 键、锁、旋钮、滚轮、翻页这些交互 | 音乐；谱面；谱种 | 哪个键、按下 / 松开 / 滑动 |
| 输入法（键 → 指令） | 乐理知识（读表）；叠音观望、单声护栏、/2 和升降的锁；每个键现在有没有意义 | 像素；现在是哪种谱面 | 指令；试听哪个音 |
| 核心：谱 + 光标 + 指令引擎 | token、时刻、写法（第 3.5 节）、谱 → 格子的换算 | 像素；键；谱种 | 新的编辑状态 |
| 谱面 | 像素 ↔「哪个音 / 哪个时刻」；手势 | 键；乐器是谁（宿主告诉它）| 指令；「这里要开菜单」 |
| 纸面的框架 | 纸、分行分页、歌词、间距、版面家具 | 五线、数字、任何字形 | 版面数据 |
| 一行的画法 | 自己的字形；纵向的意思 | 别的行；纸；分页；键 | 这一行的图元、点击框、要占多宽多高 |
| 记号表、音级读法 | 每个记号的名字 / 说明 / 各种谱里的画法 / 键面 | 谁在用它 | 表 |

「不许知道」做成结构守卫（测试查 import）：行的画法和框架不 import 键盘、界面、app；键盘不 import 排版和谱面。

### 3.2 两层接口

- **第一层：谱面。** 谱面板里放的那一块。现在只有一块（纸面，`ScoreView`）；以后 tracker、串珠各是一块。它向 app 要的东西就是现在的 `ScoreViewHost`。
  - 现在 `ScoreViewHost` 有 33 个成员，其中 9 个是「点了某样东西要开菜单」，10 个左右是纸面自己的看法（折行、分页、横卷、缩放……）。收窄之后是五样：编辑状态的读和写；歌的显示设置和设备上的看法（各一个对象）；试听；「按在什么上了」（一个事件，目标是带类型的联合）；说一句话。
  - **这一轮不为它建抽象**（只有一个实现）。只做收窄，并且守住一条：谱面改谱只走核心的词（指令和编辑状态），不自己拼。
- **第二层：纸面里一行的画法。** 这一轮真正要建的接口，见下一节。

### 3.3 纸面：框架调行的画法，分两遍

现在：`engrave(歌, 选项) → 版面数据`，一个函数从歌名画到最后一个音。

目标：

1. **预处理**（共用，和画法无关）：每张纸、每个要画的声部 → 一条「排版用的轨」：按 C 调看的换算、合租的并行、每个 token 的时刻、小节（含自动小节线和补齐的空小节）、和弦认出来的读法、哪些和弦折叠。
2. **谱种 = 一张表**：这张纸排哪几行、每行吃哪几条轨、用哪种行的画法。五线谱：有音高的声部用五线、整套鼓用五线鼓谱、单件鼓用一线谱、合租叠成一行。简谱：有音高的用数字行、鼓用 X 行、合租各占一行加一条竖线。隐藏的声部在哪种谱里都是细行。
3. **第一遍，量**（行的画法）：一条轨 → 按时刻排好的一列一列，每列说自己的墨往左、往右各占多宽，这一列管多长的时值。不出坐标。左边挂的东西（琶音线、升降号、以后的倚音）算在「往左占多宽」里，这就是 UX 稿说的顶杆。
4. **排**（共用）：同一行谱里所有声部的列按时刻对齐 → 弹簧 + 顶杆算出每一列的横坐标 → 断行 → 拉齐（最多拉宽 1.3 倍）。出每一行的**时间尺**（第 3.4 节）。
5. **第二遍，画**（行的画法）：拿到每一列的横坐标 → 出图元、点击框、这一行上下各占多高、只有自己读得懂的一小份数据（五线谱 = 顶线在哪；简谱 = 基线在哪）。
6. **叠**（共用）：行往下叠、歌词让路、分页、版面家具。

为什么分两遍：验收项「扬琴折叠 + 琶音让位后，bongo 每小节八分仍等距」只有在「所有声部先报宽度、再一起分」的时候才做得对。样张脚本不均匀就是因为每个声部各排各的。

行的画法另外给三个纯函数（在主线程上用，只吃平数据）：光标在这一行长什么样；鬼音符长什么样；（可选）纵向 = 音高：这个高度是第几级、竖着拖了这么远是几级。五线谱有第三个，简谱没有；没有的谱，谱面就不提供竖着拖改音高。现在 worker 过线时把三个闭包拆掉再装回去的做法（`stripLayoutFns / attachLayoutFns`）由这三个函数取代。

行首要重画的东西（五线谱每行开头的谱号和调号；简谱变了才写的「1=」）：框架断行时向画法要「在这个时刻开一行，行首要多宽」。

### 3.4 时间尺：横向只算一遍

每一行谱带一把时间尺：一串（时刻，横坐标）的对照，中间按直线插。它是「排」那一步的副产品。

用它的：播放的小节底色和音的高亮；听模式「从这儿放」；以后鼓格子的「点在第三拍后半拍」；以后 tracker / 串珠（它们的整块谱面就是一把时间尺加另一根轴）。

现在这些各有各的算法（`measures`、`bars`、按音找）。有了尺，画法不用再各出一份。

### 3.5 写法归核心，只有一种（修订 1，2026-11-11 夜 user 定）

第一稿写的是「两种光标、两种写法（推着写 / 盖着写）」。user 当晚把规矩统一了（谈话日记 §75–§77），这一节按新的写。**这是输入规矩，属于下一轮，不进这一轮的施工。**

- **地基**：一条线上，一个音最长响到下一个音开始；和弦同长。tracker、钢琴格都靠它。
- **写一个音（或休止）**：从光标开始，占长短旋钮选的长度；撞到下一个音或人插的小节线就停（自动画的小节线不挡，长音跨过去照旧画成连着的两段）。正对着的那个音被换掉，歌词由新音接着。后面紧跟的休止可以被占。被截短时，挡着的那个音闪一下（旋钮上的长度没兑现，必须当场看得见）。
  - 旧音比新音长时，剩下的那截**变休止**（user 11-11 夜拍）。
  - 新音接过旧音身上的东西：歌词、演奏法、连线；失效的才去掉（单音上的琶音、两头音高不同了的连音线、和弦读法的钉）。先退格再打 = 擦干净了再写，不接。〔AI 提，等 user 点头；现状只接歌词〕
  - 挂在音前面的独立记号（力度、渐强渐弱、风格、调号拍号速度、谱号）原地不动。现有的「删音后两个力度记号之间没有音 = 前一个自动去掉」，AI 提议改成不自动去掉、管不到音的画灰并说明；那条当初是按 user 10-08 的例子做的，要 user 说了才改。
- **退格**：对着音 = 变成一样长的休止；对着中间的休止 = 光标退过它；对着尾巴上的休止 = 删掉。不推不拉。（现状：对着休止是删掉并合拢，要改。）
- **选中了再打** = 换掉选中的整段（现状）。要换掉不止一个音、要并音，都先选中。
- **推和拉是明着的动作，不在键盘上**：
  - 插入 / 删除一小节：小节线把手的菜单，默认这张纸所有声部一起。
  - 选中一段往前 / 往后挪一格：挪进空地，撞到音就停。
  - 删掉并合拢：选区条的删、电脑上的 Delete。
- **小节线把手**（user 拍）：只有光标所在的小节，左边那条小节线上方有一个；鼠标移到任一小节线上端才亮；长按空白处的菜单里放同样几项；听模式、打印、PDF 不画。
- **人插的小节线在编辑器里要看得出来**（user 拍）：它挡住写入、从那里重新数小节，是影响结果的状态；打印和 PDF 照旧一样。画法〔AI 提〕：顶端一个很小的形状记号，由不进打印的那一层画。现状：排版里两种分得开，画法上没找到区别。
- **选中和拖动**（user 的方向，谈话日记 §78；做法 AI 提、没拍）：框 = 选一段，点 = 选一个东西；同一份碰撞箱管 亮 / 点 / 拖 / 框选，选中画的框 = 碰撞箱；亮着框的东西能拖——鼠标移上去就出框、按下直接拖，触屏点一下出框再拖（user 11-11 夜提，§80）；框选从空白处起拖；点空白 / 从空白起拖 = 取消选择（user，§82）。音的拖动（§81，没拍）：只管上下；鼠标和笔拖单个符头（所以碰撞箱要每个符头一个），手指用把手、不按一比一——正好对上第 3.3 节「纵向 = 音高」那个可选的几何函数：五线谱按几何算，简谱和把手按传动比算。= 第 3.9 节守卫 5「点击只指 token 或版面家具」的延伸。
- **连带改口**（现在会挪后面的）：拉长键不够长时、选区的减半 / 加倍 / 附点、剪切、粘贴、横拖改时值。变短 = 空出来的变休止；变长 = 只占后面的休止；剪切留休止；光标处粘贴只落空地，选中了再贴 = 换掉那一段。
- 光标现在只停在两个 token 之间。以后鼓格子、tracker 让它能停在任意一格上，**写法还是这一条**。新音落在一个音中间时：那个音在新音前面的部分留着（它的起点没动），后面的部分不留。
- 三条不变量，做成测试，所有谱面都靠它：
  1. 一步写入之后这条线的总时长不变（明着的插入 / 删除除外）。
  2. 除了正对着的那一个，别的音起点和长短都不变。
  3. 结果是一串合法的 token：换一种谱打开一模一样。
- 数据不变：还是一串、相对时长。不是 2026-10-10 否掉的「音存绝对位置」。
- **复音**：一个声部里不装长短不一的重叠。独立的节奏 = 另一条线。user 的方向「一个乐手演几条线」（W-64，必须要）= 乐手和线分两层：几条线并在这位自己的谱上、混音台一条通道。要动数据模型和文件格式，下一轮先出设计。user 同晚拍：只有能叠音的乐手才有几条线；两个人一起唱双声部 = 两位不同的乐手。

### 3.6 键盘：键 → 输入法 → 指令

现状三层都宽：小键盘对宿主 23 个回调（`PadHost`），宿主的胶水对 `main.ts` 32 个访问器（`PadGlue`），叠音观望和单声护栏的状态机夹在胶水里（`pad-host.ts`）。电脑键盘走另一张表（`keys.ts`），MIDI 走第三个入口。

目标（**键盘重构那一纪元的方向，这一轮不施工**）：

- **键盘前端库**：一块一块的键面（音、符、词；以后和弦、鼓、大键琴）。每块 = 一张键的布局 + 交互原语。出的只有键事件。一块键面上画什么字，读记号表和音级读法，不自己画。
- **输入法**：一个深模块。进：键事件（小键盘、电脑键盘、MIDI 三个来源同一种）+ 只读的输入上下文（编辑状态、能不能写、能不能叠）。出：指令 + 试听。叠音观望、单声护栏、/2、升降、叠这些锁都在这里。
- 3 岁大键琴、和弦键盘、鼓键盘（W-24）都是「多一块键面 + 输入法里多一张翻译表」，不碰谱面，不碰核心。
- **每个键现在有没有意义，由输入法回答**（一张表：编辑状态 × 键 → 有没有意义、为什么）。键盘只照着画：没意义的灰掉、按不动、位置不动，不藏。「台上这位不认」是另一种灰（照样能写），两种长相分开。出处 = user 11-11 夜（W-65）；做法是 AI 提的，没拍。
- **这一轮为它做的只有两件**：建记号表和音级读法（显示先用），守住「排版和谱面不 import 键盘」。

### 3.7 歌的显示设置，和修改锁

- 歌里加（照现有习惯，只写不是默认的）：谱种；和弦标级数；按 C 调看；每个声部的和弦选项。现有的版式（舒适 / 紧凑）、音距、歌词排法、小节号不动。
- 代码里只有一个地方把这些读成一个「怎么看」的对象，排版只吃这个对象，不到处读歌的字段。
- 这些不放进视图态（score.json 的 `view`：存的时候顺手带、不标脏、不进撤销的那一类）。它们决定这首歌怎么印，和版式、小节号同一类：进撤销、会标脏。
- **每轨的和弦选项三档**：只认叠在一起的和弦 / 也认拆开弹的和弦（默认）/ 折叠成和弦名。折叠只折叠在一起的、能还原的；拆开弹的照样只标级数。现有的 `brokenChords: false` 读成第一档，升级时换成新字段。
- **格式**：这些都是可选字段。旧版 app 打开新歌：不认识的字段原样带着，歌照开照存，只是按五线谱画、和弦选项回默认。按家族的格式纪律这是「缺功能、行为有变化」那一级（能开能存，提示一次）。升一拍、加一份冻结样本。
- **修改锁**：这些设置归「看法」那一类（`edit-lock-table.ts` 里和「曲段隐藏」同一类）。锁着能切；锁着期间一个字节都不写；导出和打印跟着眼前的样子；解锁之后照常存。别人的歌锁着打开、切成简谱看、关掉，文件没动——这正好是纪要 §27 说的「读的人换着看」，不用另做一层设备设置。
- 后果要说一声：「和弦标级数」「按 C 调看」现在存在设备上。搬到歌里之后，以前在设备上调过的不带过去，每首歌回默认，要改就在歌里改。

### 3.8 记号表、音级读法、排版参数表

- **记号表**：一个记号一行——名字、点一下的说明、放在数字上方的哪一道、每种谱里画成什么、（下一轮）键面上画成什么。「每种谱里画成什么」这一栏的类型是「每种谱都必须有」：加一个记号或加一种谱而漏填，编译就不过。记号的 id 用现有的（`Art`、`Dyn`、小键盘的键 id）。
- **音级读法**：音 + 调 → 第几级、升降、几个八度点。现在 `clipboard.ts` 有一份，搬到核心，简谱画法、小键盘、剪贴板三处共用。八度基准（UX 稿：按乐器音域定）由宿主算好，放在声部的信息里传进来，和现在的「是不是单声乐器」「是不是鼓」一样；排版不认识乐器目录。
- **排版参数表**：一种版式 × 一种谱 = 一行数。每个数是一个独立的量，分三组：横向（间距曲线、字边留白、最小间隙、最多拉宽多少、最多压紧多少）、纵向（各道之间、歌词距离、声部间距、行距）、字（比谱大多少、歌词压窄多少）。框架那一层的量用毫米；行里面的量用这种谱自己的单位（五线谱 = 线间距，简谱 = 数字的高）。现在散在 `engrave.ts` 的 `SPACING`、`paper.ts`、`spacing.ts`、歌词模块里的常数都收进来。调版式 = 改这一个文件。
- 简谱数字的宽高进表（像现在 Bravura 字形的 `glyph-box.gen.ts`），排版不现场量数字。现场量的只有歌词和名字。

### 3.9 守卫（做成测试）

1. 结构：第 3.1 节的「不许知道」查 import。
2. 版面数据是平数据：过一次 worker 的拷贝，逐字段相等；几何函数只吃平数据。
3. 分家不变样：冻结的样本歌，分家前后图元逐个相同。
4. 全量：
   - 记号表类型上每种谱都有（编译期）。
   - 一首把每种 token、每种修饰都用一遍的测试歌：每个 token 至少有一个图元指着它；每样修饰都在画法报上来的「画了什么」清单里。
   - 一个图元最多属于一个 token（现在结构上已经是这样）。
   - 隐藏的声部有细行。
5. 点击只指 token 或版面家具：每个点击框带「哪条轨第几个 token」或一个家具的名字，不带字形的名字。简谱的横线、下划线、一拍一个的 0，点了都是它所属的那个音。
6. 性能（数次数，不比墙上钟）：改一个音，「量」只跑这一条轨；挪光标、选区、播放高亮，排版 0 次。
   - 〔2026-11-11 夜：拆成两半。前一半 = 排版次数不比现在多、挪光标 / 选区 / 播放高亮 0 次，第一刀立。后一半 = 改一个音只量一条轨，是新的缓存，不和分家掺在一起做；什么时候做、怎么守见施工单第五节裁定 2。〕
7. 锁：显示设置那一类看法，核实只动了那几个字段。
8. 同样的输入出同样的版面：排版不读界面语言、设备设置、时钟。

### 3.10 性能

- 现状（任务书记的）：大歌 1204 个 token 一次排版约 28 毫秒；挪光标和选区不排版；按行重画。
- 歌是结构共享的（改一条轨，别的轨还是同一个数组；`withTrack`，锁的那张表也靠这个）。所以「量」的结果可以按轨缓存：键 = 这条轨的数组本身 + 和它有关的显示设置。改一个音只重量一条轨。
- 「排」是纯算数，整张纸重算。「画」按行缓存：这一行的列坐标和轨都没变就不重画。
- worker：现在每次把整首歌拷过去（`LayoutJob.song`），拷完数组就不是同一个了，按数组缓存会失效。方向：worker 里留一份歌，主线程只送变了的轨和它的版本号。**先量再做**：拷贝占 28 毫秒里的多少我没量，占得少就不做。
  - 〔2026-11-11 夜，小弟量的（node 里，假尺子；浏览器里比例只会更小）：大歌全部视图，发过去的拷贝占一次排版的 3.6%（0.73 / 20.4 毫秒）；回来的那一份（版面 + SVG 字符串）1 MB、4.7 毫秒、占 23%。拷贝之后数组身份没了，所以「按数组缓存」在 worker 里永远不中：要缓存就得主线程按数组身份发版本号一起送。现在两样都不做。细节 = `20261111-engrave-cut-map.md` 第六节。〕
- 多一种谱不加排版次数：一次只排当前的谱种。
- 预算：分家那两刀之后，同一首大歌的排版次数和「量」的次数不许比现在多；时间只报告、不卡。

三件关于钢琴格和 tracker 的判断：

1. **tracker 可以完全做成 token 的另一张皮，而且不会有拖不动**，前提是盖着写在核心里、守住第 3.5 节那三条。要 tracker 那一纪元才定的：一拍几行；落不到行上的「延后」记号怎么显示和怎么改；歌词那一列。
2. **钢琴格的三条路现在都不挡**：串珠（新谱面，现有指令）；只读（一个换算）；真钢琴格（新的轨）。前两条不用改宪法。第三条要改，而且歌词和小月相那一头要另想（格子轨给不了她音节）。我不替 user 选；这份架构只保证选哪条都不用推倒现在做的东西。
3. **「谱 → 格子的换算」必须是核心里的一个函数，而且只有这一个。** tracker、串珠、只读钢琴格、走向线、时间线的出声，读的都是同一份「写的音」。各算各的，迟早有两处对不上。

## 5. 这份设计自己的弱点

1. 两遍的协议对五线谱是不是合身，我没有读 `engrave()` 的函数体。符杠、连线要等横坐标定了才画，这在第二遍，没问题；拿不准的是它现在的间距和画是不是缠在一起。所以五线谱先走「旧排法」过渡，第一刀先让施工侦察、报一张「哪段归框架、哪段归五线谱」的表，再切。
2. 过渡期框架里有两条间距的路。退场条件写了（刀 6）；如果刀 6 一直不做，这就成了永久的双轨。到简谱多声部做完还没排刀 6，要回来看一次。
3. 谱面那一层只有一个实现，接口是照现状收窄的，没被第二个实现检验过。tracker 开工时它很可能要再改一次。所以现在不建抽象，只收窄。
4. 新的写法规矩（第 3.5 节）是纸上的设计，没有原型。施工前值得先做一个丢掉的原型，验三条不变量和手感。
5. 记号表「每种谱都必须画」对 tracker 这种谱可能勉强（只能写缩写）。这是「全量」规矩的直接后果，我认为对；到时候不好看是画法的问题，不是不画的理由。

## 8. 要 user 拍的

1. **总方向**：第 1 节那五句。尤其是「热插拔的单位是一行的画法，不是整页的引擎」和「写法归核心、由光标的种类决定」。同意的话我把它记成一条 ADR。
2. **施工顺序**：先两刀分家（看不见变化），第四刀才出简谱；五线谱的间距放最后改，改之前先给对照样张。另一条路是先抄一个简谱整页引擎，简谱出得快一刀，但之后每个版面功能做两遍，而且合回来那一刀很可能一直不做。我推荐前一条。
3. **动歌的文件格式**（第 3.7 节）：加四个可选字段，升一拍；「和弦标级数」「按 C 调看」从设备搬到歌，以前在设备上调过的不带过去。
4. **简谱第一天能不能打字**：按这份架构，现在的键盘在简谱下直接能写，只是没有竖着拖改音高。推荐：能写。想先只读，也只是锁那张表里加一行。
