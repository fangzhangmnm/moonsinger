## 6. AI 的读法（未拍板）

1. **简谱 + 数字键盘 ≈ 原来的心智模型（一半）**：08-18 的起名哲学是「nokia的彩铃编辑器」。peek 核实（Nokia 2310 说明书 https://manualslib.mx/manual/75261/Nokia-2310.html?page=40 ）：1–7 = 音符、0 = 休止、8 缩短 / 9 延长当前音、* 设八度、# 升半音——数字键入和简谱同一套；**但 1 永远是 C（固定调），不是首调**。首调是简谱多出来的一层。
2. **简谱天生是唱歌的记法**：首调——转调只改「1=C」一处，不碰黑键（user 08-18 说过怕转调和多黑键）；「-」和下划线是离散时值（治「piano roll 不知道拖多长，总是差两倍」）；歌词一字一音写在音符下面，是中文儿歌本的原生排版。user 平时在聊天里写旋律就是这个格式（如 `65 1- | 1- 2-`）。
3. **《小兔子乖乖》样张里的结构**（AI 看图描述）：头部「1 = C　2/4　中速　民间儿歌」；四行谱，下划线 = 八分音符，带连音弧和高音点；每行下面两行歌词 = 两段词共用一条旋律；词前标角色——（大灰狼唱）/（兔妈妈唱）/（小兔子唱）。即：一首儿歌本身就有「谁在唱哪一段」，是对唱。
4. **排练室以她为圆心**：有了歌手，舞台就有中心；伴奏乐器围着她摆，远近 / 左右 = 混响 / pan。物化可能只需要一张俯视图，不需要 live2d。（2026-10-07 user：「颠覆之后live2d小人俯视图已经没啥必要了，是obsolete」——俯视图 / 小人作废；edited by Claude Fable 5.1）
5. ~~「低配版 live2d anchor」= WXHW 参考窗里的立绘~~ → 被 user 当天订正，见 §3「图片 / stamp」：是乐谱里一张贴纸级别的图。

## 7. 音乐史闲聊：作曲家用嗓子摸 spine（user「这一段都记账」）

**触发（user 原话）**：「以后做非人声的也可以让月读先摸旋律线，我缺的就是spine，我估计贝多芬也是这么做的。话说贝多芬和莫扎特这帮人会唱歌吗，这个是必修吗。有没有哑巴成为音乐家的励志小故事。交响乐应该是这么写的吧」；「说不定可以根治我坐在琴前面有灵感没daw坐在电脑前面有daw没灵感的问题。让月读当那块肌肉」。（对照 08-18 原话：「IV V iii iv已经可以generative model永动了。但是没法commit，做到电脑前面就blank canvas」。）

**AI 当场的回答**（照录；AI 凭记忆讲的，每条后面标核没核）：

- **贝多芬确实是这么干的。** 学生 Ries 回忆过：有一次陪他散步，他一路哼、一路嚎，忽高忽低，唱不出确定的音，一到家就扑到琴前弹出了《热情》的终曲。【核到：Henle 版《热情》介绍转述 Ries「had the whole way been humming to himself or sometimes howling」，https://www.henle.de/us/Piano-Sonata-no.-23-f-minor-op.-57-Appassionata/HN-1587 】他的草稿本里大多也是单行的旋律线。【未核】嗓子难听，照样用嗓子先摸出 spine。
- **莫扎特更直接。** 他的草稿通常是先写最上面的旋律和最下面的低音，中间的声部和配器之后再填。《安魂曲》没写完就停在这个状态：人声和低音是全的，乐器只留了提示，后来由学生补完。他还在信里说过，一首咏叹调要贴合歌手，像一件裁剪合身的衣服。【均未核；信大约是 1778 年写给父亲的】数据契约围着歌手的嗓子长，这事 250 年前就有人在做。
- **唱歌是不是必修：** 那时候的入行路线基本是当唱诗班男孩，巴赫、海顿、舒伯特都是。贝多芬的父亲是宫廷男高音，祖父是宫廷低音歌手兼乐长。现在音乐学院里「视唱练耳」是必修，但考的是唱得准，不是唱得好听。【均未核】
- **哑巴音乐家：** 我想不起有确凿记载的哑巴作曲家，不编一个出来。最有名的是反过来的情况：贝多芬晚年全聋，第九交响曲是在脑子里听着写的。真正的必修大概是「心里听得见」，嗓子只是把它放出来的出口。你心里那部分是好的（核心记忆全能哼出来），缺的是出口，所以请月读。
  - **事后快搜补记**（同日）：没搜到哑巴作曲家（只搜了一轮，不等于没有）。搜到的最近一例是**拉威尔晚年失语**：还能在脑子里想音乐，却写不出也弹不出（出处很弱：https://visualize.jove.com/801118-aphasia-in-maurice-ravel ）。据传他说过有一部歌剧「就在我脑子里，我听得见，但我永远写不出来了」【AI 凭记忆，未核原文】。
- **交响乐是不是这么写的：** 古典时期大体是。先定旋律加低音的骨架，再填内声部，最后分配给乐器。也有从一个动机起步的，比如命运交响曲那四个音，但那个动机本身也是能哼的。【未核】

## 8. 第一公民的真正含义：乐器复用月读的旋钮命名（user aha + AI 草想，供参考）

**user 原话（同日）**：
- 「不要被儿歌和be human给限制住了。我说让月读逼出编辑器的形状，技术还是需要尊重的」——针对 AI 把旋钮砍成「松紧、气息两根滑条」的畅想；初音那十个旋钮、DiffSinger 那几根曲线都要尊重，zen 的意思是不藏进面板，不是砍掉。
- 「关键的aha在于，让器乐去复用月读的旋钮的命名规范，而不是让月读去复用器乐的旋钮的命名规范。这个才是第一公民的真正含义」
- 对下面映射表和歌词位一段：「落盘，到时候可以参考」。

**AI 的读法**（未拍板）：
- VOCALOID 恰好是反着做的：V2 里管「辅音长短」的旋钮名叫 VEL（Velocity）——这是 MIDI 的词，原意是琴键按下去多快；编辑器也是 MIDI 钢琴卷帘。初音是被塞进乐器词汇表的歌手；MoonSinger 反过来，乐器拿歌手的词汇演奏。（V2 参数表出处：https://vocaloid.fandom.com/wiki/Using_the_Parameters ；「VEL 借自 MIDI」是 AI 的读法。）
- 技术上行得通，因为嗓子的旋钮在物理上本来就和具体乐器无关。DiffSinger（OpenVPI 版）的定义（出处：github.com/openvpi/DiffSinger `docs/BestPractices.md`，子 agent 转述）：**气息** = 噪声部分的响度；**实声** = 谐波部分的响度；**张力** = 基频那条谐波占全部谐波的比例。任何「有音高的声音 + 噪声」都能这样拆。这正是 08-18 user 要的「无convention, physically well defined的spec」。

**映射草想**（AI 写的，原样落盘）：

| 月读的旋钮 | 落到乐器上 |
|---|---|
| 气息 | 长笛的气声、弓噪 |
| 张力 | 弓压、铜管吹得多狠 |
| 实声多少 | 乐音和噪声的比例 |
| 嘴张多大 | 铜管的弱音器、哇音（搋子弱音器本来就在模仿嘴型） |
| 男女声感（共振峰） | 琴体大小：小提琴 → 中提琴 → 大提琴，很像把共振峰往下挪 |
| 辅音长短 | 起音：管乐吐音本来就是用 tu / du / ku 发出来的；弦乐是弓头那一下 |
| 滑音、颤音、音高线、音量 | 原样通用 |

**歌词位也复用**（AI 写的，原样落盘）：乐器的歌词就是起音的音节。管乐吐音念 tu-ku、ta-da；日本太鼓教学用「口唱歌」（ドン、カッ、ツ）；三味线念「テン、ツン、チン」。日本传统音乐本来就用嗓子的音节来记乐器，乐器复用歌手的规范，这事早就有先例。【口唱歌与吐音音节均为 AI 凭记忆，未核出处】

**落到数据上**（AI 草想）：每个音符都有一个音节位（唱的是歌词，奏的是起音音节）和同一套嗓子曲线；钢琴、鼓也不例外，只是有几根曲线对它们没意义（钢琴没有气息）。
