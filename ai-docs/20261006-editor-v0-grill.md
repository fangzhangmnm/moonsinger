## 2. 写作心理：只管「写什么」，不管「写在哪」

- user 的问题：「思考一下写作心理学，什么能最快写出来，钢琴格我真的会blank canvas syndrome吗。还是只是因为不知道时长的约定所以第一个音zoom不对不知道是C几不知道是几格然后开局就被踢出去，我觉得你也知道我们家族的核心卫生就是怕用户被踢下去，这是我们的zen，而不是一味地anti bloatware minimalist」；「其实我识谱能力比不上专业学生的。碰到升降号多的谱线会死。但为什么我总是想回避钢琴格，觉得钢琴格没有语义，五线谱有语义呢」。
- AI 的回答（要点）：
  - 钢琴格两根轴是物理单位（半音、格），五线谱 / 简谱是音乐单位（音阶级、拍）。钢琴格 12 行平等，说不出「在不在调里」；长度只能量不能读；祖宗是自动钢琴纸卷，给机器读的。
  - 五线谱的语义钉在 C 大调坐标上，调号是补丁，远调要先在脑子里换算——这是「升降号多就死」的来源；简谱把同样的语义放在对的坐标（「5」就是属音）。
  - 开局踢人的三个点：竖轴没锚（C 几）、横轴没锚（拖多长）、每个音都要在平面上定两个坐标。旋律是一串，像一行字；打字时光标自己往前走。
  - 记忆里的歌是相对的（几级 + 节奏），绝对音高界面要每个音翻译一次。
- user：「你只管「写什么」，不用管「写在哪」 同意，这个是一个非常重要的结论」。
- user：「嗯，先写，杀decision fatigue，我觉得开局护栏就是这个」。

## 7. 每个乐器的默认音阶 + 音域（AI 本轮的回答，未认）

- 合理，而且有物理依据：很多乐器天生只有一套音——古筝定弦五声（4、7 靠按弦）、十孔口琴一个调（压音补）、锡口哨一个大调（半孔补）、竖琴七声（踏板改）、卡林巴、钢舌鼓等。「默认引导 + 越狱」正对应「天生的音 + 演奏技巧」。
- 分两层：**调（1=G）属于这首歌 / 这一段，所有声部共享**（不然和声对不上）；**每个声部自己的是「音阶滤网 + 音域」**。
- 滤网和音域只是引导，不进音符数据：音符存「几级 + 升降 + 八度」，换滤网不动任何一个音。
- 配器的默认音域可以替她让路：铃铛在她头顶、低音在她脚下、钢琴左手在她下面——「配器必须是为了给月读伴奏」落成默认引导。

- 小调：AI 推荐 6 当主音（la 小调；大调 / 小调 / 五声住同一组行，只差哪行高亮当主音，宫商角徵羽 = 1 2 3 5 6 谁当家）。user：「6主音可以啊」。

## 8. 原点：缺的是冰点，不是绝对零度

- user：「停一下，可能我制作与五线谱的原因很幼稚：C0 C8和高音低音谱号对不上。可能只是因为这个，先帮我科普一下，然后刚才的回答重写」。
- **事实**：中央 C（MIDI 60）教科书 / MuseScore 叫 C4；**FL Studio 叫 C5**（八度号从 0 起，最低音 C0）；**Cubase、Ableton 叫 C3**（雅马哈传统）。同一个键三个名字。出处：Novation 支持页 https://support.novationmusic.com/hc/en-gb/articles/4886437587474 、Steinberg 论坛 https://forums.steinberg.net/t/middle-c-c3/605045 （10-06 WebSearch，二手转述）。
- 对照（教科书编号）：中央 C = C4 = 高音谱表下加一线 = 低音谱表上加一线；高音谱表五线 E4 G4 B4 D5 F5、四间 F4 A4 C5 E5；低音谱表五线 G2 B2 D3 F3 A3、四间 A2 C3 E3 G3；编号在 C 处进位。
- user：「然后同意我也是只是缺了一个原点。时长的普朗克时间和音高的绝对零度。统计物理公式用开尔文简单。但是中国和美国工程师在C和F上面互相鄙视，但没有见过谁用K的。你想想为什么」。
- AI 的回答（要点，未认）：K 是给公式乘除用的比例尺，零点真实但在没人活的地方（日常 250–310 K，首位永远是常数、没有地标）；℃ / ℉ 把原点挪到生活里的地标（结冰；温带天气与体温），正负号本身有意义。C 和 F 吵的是原点放在哪个地标，「原点必须在生活里」两边一致，所以没人用 K。音乐里：赫兹 / MIDI 号 / C0–C8 = K（DAW 吵 C3 / C4 / C5 = 吵 K 尺的偏移）；简谱的 1、大谱表的中央 C = ℃。时间：秒 / tick = K，拍 = ℃，最小格 = 一拍的几分之一，跟拍走不跟缩放走。→ **缺的原点是冰点不是绝对零度**；乐谱存 ℃ 尺（几级、第几拍），引擎在接口那边换算成 K 尺（赫兹、秒），换算常数一首歌只存一次（「1=G」）——和 §1「乐谱不存引擎的东西」同一条。

## 8½. 第一版范围（Q12，user：「同意」）

- **做**：一张浏览器试验页（刷新即清空，同 CatsUp 起步）；一行真五线谱（高音谱号、调号、拍号、自动小节线、歌词在音符下）；一串 token（带拼写的音高可空、时值、歌词可空、休止 0）；三路输入写同一串——电脑键盘、指针（鼠标 / 笔：点线间、上下拖改音高、拖尾改时值且吸附）、手指 pad（MEDO 五度折行、跟调）；歌词打一行自动一字（日文一假名）一个 token；播放 = 月读在浏览器里唱（Lab 唱法搬进后台线程）。
- **不做**：存档、撤销、表情曲线、会跳的律动、伴奏、多声部、导出 mp3、iPad 速度优化。
- **验收**：用它打完《うさぎ》、点播放听她唱；浏览器版同谱固定种子的波形与 Lab Node 版逐样本对上（只查代码对不对；好不好听归 user 耳朵）。
- 未验证的工程猜想：日语前端 103 MB 主要是汉字→读音词典，歌词已是一音一假名时也许用不着 → 日语可能降到 ≈ 56 MB。第一版先照 Lab 原样搬。
- user 补的 token 好处：「token还有一个好处是咿咿呀呀的时候不用管时值，之后可以调，而且一个时值判错了改的时候后面自动适应，这个也是token based的好处」。
- 电脑键盘：user「电脑键盘用1234567?支持小键盘（虽然我没有）」。AI 草案（未认，升降 / 八度键做出来再调）：1–7 = 调里第几级（八度就近，与 pad 一致：手相对、眼绝对）；0 休止；8 / 9 = 刚打的音减半 / 加倍（诺基亚原样）；- 拉长一拍；. 附点；' / , 上下八度（小键盘用 * / /）；# / b 临时升降。按字符绑定不按物理键位，小键盘白送。

- **小节线是 token**：user「还有一个很大的结论就是bar是你人工插的token，而不是定好的护栏」。→ 推翻 AI 先前默认的「小节线自动画、跨小节自动连」（Q6 末尾那句）。AI 的读法（未认）：哼完再往强拍前插「|」；弱起自然有；拍数与拍号对不上只轻标、不拦（家规不许规训）；强拍 = 「|」之后（以后猫娘大跳落这里）；键盘「|」，小键盘 Enter 候选，pad 旁的按钮条加一个。
- **Shift = 上档**：user「其实我想的是shift-1 是大写的1就是上一档这种感觉？然后ctrl是anti-shift? 不知道这样是否可靠」。AI 的评估：主键盘 Shift+1–7 可靠（按物理键位 event.code 认，不按字符）；Shift+小键盘在 Windows 不可靠（NumLock 下变 End 等，AI 凭记忆）；Ctrl+1–8 在浏览器是切标签页（Mac 是 Cmd），反 Shift 另找（Alt / Option，或事后按「,」），实测再定。AI 提的语义（未认）：不按 = 就近；Shift = 从上一个音往上找这个音；往下键 = 往下找（只想方向，不用算是否超过四度）。

- 方向语义 user：「赞，往下键是什么？ctrl用不了的话，能和上下方向键做同按检测吗，不过上下方向键是调音高的」。AI 答（未认）：和方向键同按能检测但不建议（按下即已调音、要等松开才知是否同按、按住会连发）；Alt 也不稳（Linux Firefox / 可能 Chrome 用 Alt+数字切标签，Windows 松开 Alt 会跳菜单——凭记忆）。**推荐数字键正下方一排 Q W E R T Y U = 往下找的 1–7**（无修饰键、按物理位置认、「下一排 = 往下」）；小键盘打完按 `/` 往下翻、`*` 往上翻。连带：Shift+3 已是「往上找 3」→ `#` 打不出 → 临时升降改走方向键：↑↓ 调内一级、Shift+↑↓ 半音、Alt+↑↓ 八度（Mac 的 Ctrl+↑↓ 被系统占，凭记忆）。全部做出来实测再定。
