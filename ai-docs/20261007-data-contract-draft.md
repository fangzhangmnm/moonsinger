## 0. 一句话

一首歌 = 一个 `.mxl`（MusicXML 官方的 zip 形）。主体是标准 MusicXML（别的软件能开、能看、能放）；我们自己的东西是 zip 里的扩展文件，每份自带版本号、各自迁移（user 10-05「和ora一样尽量用已有的开源格式」「每个模块有一个自己的版本号拍子。然后有一个独立的迁移模块，尽可能瘦」）。

## 2. .mxl 完整目录表（提案）

照 WeebPaint 动 .ora 布局的规矩：每次改这张表都要报 user。

| zip 里的路径 | 归哪块 | 内容 | 版本号 |
|---|---|---|---|
| `mimetype` | 标准 | `application/vnd.recordare.musicxml`；必须是第一个文件、不压缩 | — |
| `META-INF/container.xml` | 标准 | 第一个 `<rootfile>` = `score.musicxml` | — |
| `score.musicxml` | 谱（标准部分） | MusicXML 4.0：声部、音符、休止、歌词（每音节 `xml:lang`）、调号 / 拍号 / 速度、和弦记号（`<harmony>`）、叠音（`<chord/>`）、力度（`<note dynamics>`）、音符 `id`。每个声部的乐器（GM 号、`instrument-sound`）和音量 / pan 是**给别的软件的压平视图**——我们自己读时以下面几份为准 | MusicXML 4.0 |
| `moonsinger/manifest.json` | 总目录 | 下面每份文件在不在、各自的版本号、写它的 app 版本 | 1 |
| `moonsinger/score.json` | 谱（扩展） | MusicXML 装不下的谱上的东西：哪些小节线是人插的（自动的不进数据）、还没写音高的音（先写歌词那种）、编辑器要的 token 顺序信息；按音符 id 对号 | 1 |
| `moonsinger/curves.json` | 谱（扩展） | 曲线：按音符 id；名字 = 月读的旋钮名；时间 = 音里 0–1；数值三类 | 1 |
| `moonsinger/casting.json` | 选角（窄接口） | 声部 id → 成员 id（上场前选角色） | 1 |
| `moonsinger/members/<成员 id>.json` | 排练室快照 | 这首歌用到的每位成员一份：名字、GM 号 + 变体、哼的字、响度校准（看得见、能调的默认，dB）、引擎参数（按引擎名分组；**不认识的引擎那组原样写回**） | 每份各自 1 |
| `moonsinger/mix.json` | 混音 | 按声部 id 的通道：推子（dB）、pan、「按谁混的」（成员 id，换了成员时标出来、不自动重置）；效果以后加 | 1 |
| `attachments/…` | 挂件 | 封面、参考图；在 manifest 里列出 | — |

不认识的文件（以后的版本加的、别的工具加的）：读时留在内存里，存档时原样写回。

## 3. 谱：我们的 token ↔ MusicXML

| 我们的 | MusicXML | 备注 |
|---|---|---|
| 时值（TPQ = 1680） | `<divisions>1680</divisions>` + `<duration>` | 1680 = 2⁴·3·5·7，三 / 五 / 六 / 七连音都是整数；显示用 `<type>` `<dot>` `<time-modification>` |
| 带拼写的音高 | `<pitch><step><alter><octave>` | |
| 休止 0 | `<rest/>` | |
| 连音线 | `<tie>` + `<notations><tied>` | |
| 小节线（人插的 / 按拍号自动的） | `<measure>` | MusicXML 必须分小节：两种都写成小节，哪些是人插的记在 `score.json` |
| 调号 / 拍号 | `<attributes><key><fifths>` / `<time><beats><beat-type>` | 中途的写在发生的那个小节里 |
| 速度 | `<direction>` 里的 `<metronome>` + `<sound tempo>` | 速度的文字（Andante…）由数字推出来，不存 |
| 歌词 + 「这个词没完」 | `<lyric number="1"><syllabic>` + `<text xml:lang>` | begin / middle / end / single 由 hyph 推 |
| 叠音（留位） | 后面几个 `<note>` 带 `<chord/>` | 月读只唱最上面那个 |
| 和弦轨（留位） | 第一个声部里的 `<harmony>`，`<offset>` 落在拍上 | |
| 力度（留位） | `<note dynamics>` / `<dynamics>` 记号 | |
| 音符 id | `<note id="n17">` | 编辑时不变、复制粘贴时换新；曲线、score.json 都按它对号 |

现在挂在整首歌上的「哼的字」（`Song.hum`）→ 搬到月读这位成员的配置里。音质（完整 / 轻量）、模型来源、pad 布局 = 设备上的，不进文件。

## 4. 打开别的软件存的 MusicXML / .mxl

- 只有谱：声部、音符、歌词照读；没有 `xml:lang` 的歌词按自动认填（有假名 → 日、拉丁 → 英、只有汉字 → 跟前一个字）。
- 选角：按 `<midi-program>`（GM 号）找排练室里对应的成员；找不到 = 这条轨未选角、不出声、提示人选（不自动塞一个）。
- 混音：取各声部的 volume / pan 当初值。

## 5. 无地逃生口（store 之前先做的导入导出）

user 2026-10-07「先不急着store。可以先按照无地规范导入导出做逃生口」。照 WeebPaint 的无地：

- 文件菜单：「打开…」「存」「另存为…」。桌面 Chromium 能存回原文件；iPad / Safari 存 = 下载或分享一个 `.mxl`，打开 = 选文件。改过没存要有标记。
- 不需要 store、不长 gallery（家族「无库不长 gallery」）。
- 排练室在 store 之前 = 当前这首歌里的成员（快照）；跨歌的排练室要持久化，等 store（或者能单独导出一个排练室文件——未定）。
