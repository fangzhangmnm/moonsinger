> 两个纪元不一定是immediately要做的。但是是vision

## 1. 录音纪元

- 节奏提示：参考音游、但不要太花。
- 延迟补偿用的对齐（录进来的声音和谱对上）。
- 音轨的样子：vocal 轨（人录的），下面背景是谱上的音；人声代替小月相。
- 相关旧账：wishlist W-10「人录的音频（Audacity 那些活）」、W-16「黑化月读 / 唱法承重 / 录音 + 变声」。
- 要先问的：家规硬规则 #8 写的是「用户的语音/音频字节永不离开设备」。**出处核过**（2026-10-13 用 WeebPaint `tools/extract-user-feedback.py` 抽人类语料，两个通道都扫）：user 2026-09-03 在 WebXiaoHeiWu 测离线中文语音识别（麦克风听写）时说「拍板：用理智杯。然后极限小杯做一个interesting option。quest还没测，先做进webxiaoheiwu。然后系统的语音sunset.现在验收的时候语言严格禁止外发。写硬规则。以后需要外接服务需要开白名单进黄线区。」——说的是语音识别（不用浏览器 / 系统的识别、不送云端识别），「写硬规则」是 user 要的；家规里「语音/音频字节」的措辞是当时 AI 归纳的（「音频」是 AI 加的，原话「语言」多半是「语音」的笔误）。和 JustReadBooks 朗读无关。人录的 vocal 轨存进歌、经 OneDrive 同步，撞的是 AI 写的字面，不是当时说的识别外发；算不算、要不要改家规措辞，归 user 裁。

**⑦ 的两个对立方案（user 列的，没选）：**
1. 插件 / 具体的声音。
2. 乐器（包括占位）为主，再对齐到对应的插件。

两个方案都要成立的：小月相是插件，人类录音也是插件；以后能自己上传 AI 歌手；能从 OneDrive 取音源。

## 4. 要先问的（AI 看到的约束，没拍板）

- **人声录音 vs 硬规则 #8**：见 §1。
- **小月相是不是插件**：本仓 CLAUDE.md「月读与方向」（2026-10-05 颠覆）写的是「月读（つくよみちゃん）= 第一公民，内置，不是插件」；user 10-13 说「小月相也是插件，人类录音也是」。同一段 CLAUDE.md 也写着 user「今天的和之前的所有规矩都是提案，都可以随时吃书」。是吃书（小月相改成插件），还是「插件」只指数据模型里的位置、第一公民的地位不变，归 user 说。
- **云端 multiplayer**：接任何新的网络服务都要 user 先开白名单（家规「黄线区」）。现行白名单只有 OneDrive、模型包主机、音源库主机。
- **从 OneDrive 取音源**：只能经 `@internal/store`，scope 永久钉死在 AppFolder（硬规则 #6），音源文件得放在 app 自己的文件夹里，读不到网盘别处。
- **自己上传 AI 歌手**：本机导入走得通（先例 JustReadBooks 本机导入小雅）；要从新网址下载就是新主机，同样要开白名单。权重要核许可证（家规「共享模型库」）。
- **版本号**：纪元 = minor，什么时候开由 user 定（AI 不提议 minor）。
