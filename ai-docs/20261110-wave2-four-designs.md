## 一、每一段自己选谱号

user 11-09：「staves的逻辑能不能收到clef里面，或者后面四个选项应该没有，收到前面的per sheet而不是跟着歌手。只有shared staves有」「可以高音低音grand用户每个sheet选」「一开始是auto，auto也会自动变成grand，你看一下是什么规则」。

### 你会看到什么

点一行开头的谱号，开出来的面板里：

- **谱号**一个下拉框，管「这个声部在这一段」：
  - 自动（括号里写现在挑的是哪个，比如「自动（现在：低音）」「自动（现在：大谱表）」）
  - 高音、低音、带 8 / 15 的那几个（和现在一样的六个）
  - 大谱表（上高音下低音）
- **自动八度线** 开 / 关，也是「这个声部在这一段」。大谱表时没有这一行（大谱表本来就不画自动八度线，和现在一样）。
- 面板下半截「整首都算」的只剩两样：**合租**、**分解和弦认不认**。原来的「谱表」「默认谱号」两行拿掉，「跟声部」那一档也没有了。
- 一段中间换谱号的那一处照旧：只有六个谱号，没有自动、没有大谱表。

新东西从哪儿抄：

- 新的一段：上一段是自动 → 新段也自动；上一段是手选的 → 新段也手选，选上一段结尾时用着的那个；上一段是大谱表 → 新段也大谱表。自动八度线关着的也跟着抄。
- 把一个声部放进某一段：照它前面最近出现的那一段的选择（前面没有 = 后面最近的；都没有 = 自动）。这样「吉他一直用低八度的高音谱号」不用每段重选。
- 复制一段 = 原样照抄。

### 「自动」什么时候自己变成大谱表

合租的那一家照现在的规矩，不动。单独一个声部的「自动」，下面四条**都满足**才变大谱表：

1. 这一段里它至少有 8 个音；
2. 中央 C 上面的音、下面的音各占两成以上（只是偶尔低下去 / 高上去的不算）；
3. 这一段里没有手写的中途换谱号（手写了 = 你在自己管谱号，自动不插手）；
4. 排成两行比任何一个单谱号（算上自动八度线）都明显好读：平均每个音要省下相当于两条多加线的难读程度。

上一段已经是大谱表的，门槛放宽一点接着用，不来回跳（和现在自动谱号翻段不跳是同一个做法）。

照这个规矩必须成立的例子（施工时拿来当验收，数字调到这些例子都对为止）：

| 这一段写的是 | 自动挑的 |
|---|---|
| 唱的旋律，G3 到 E5，偶尔低于中央 C | 高音谱号，一行 |
| 吉他，E2 到 E5 | 低八度的高音谱号，一行 |
| 大提琴 / 贝斯 | 低音谱号，一行 |
| 钢琴两只手（低音 + 上面的和弦 / 旋律） | 大谱表 |
| 只有 5 个音，上下各几个 | 不变大谱表（音太少） |

副作用说一次：自动的那一行，写着写着可能从一行变成两行（你 11-09 说过谱号自动换没事，这是同一类）。不想它变 = 下拉框里手选一个。

在自动变出来的大谱表上，手动把某个音挪到另一行（现在就有的那个动作）= 这一段的选择同时定成「大谱表」，并说一句。原因：手分的上下行只有大谱表存得下。

### 存进歌里什么

- 手选的单谱号：和现在「这一段开头的谱号」是同一个记号，文件里的写法一个字不变。
- 手选的大谱表：写在这一段自己的那份谱里（MusicXML 自带的「两行谱表」）。以前是整个声部每一段都写，现在只有选了的那几段写。
- 自动变出来的大谱表：**不写进每一段的正本**，只在给别的软件看的那份整首的谱里照着画。这样旧版本打开不会把整个声部都变成大谱表。
- 每一段关掉的自动八度线：歌文件里这一段的条目下多一个小记录（只有关了的才写）。
- 给别的软件看的整首的谱：一个声部只要有一段是大谱表，整首就按两行写，单谱号的那几段音都在上面一行，下面一行空着（MusicXML 的标准做法）。

老歌：打开照原样画。原来「整个声部是大谱表」的 → 它在的每一段都是手选的大谱表；原来声部设了默认谱号的 → 没写开头谱号的那几段各补一个开头谱号；原来声部关了自动八度线的 → 它在的每一段都关。存一次之后就是新写法。

旧版本的 app 打开新歌：能开能改。某一段手选了大谱表的声部，在旧版本里整首都是大谱表；每段关的自动八度线回到开着。音不丢。旧版本会提示一次「这首歌是更新的版本存的」。

### 给施工的

- 现状落点：`src/score/song.ts`（`PartDef.clef / staves / autoOttava`，`headerSpot / headerVals / setHeaderAt`，`addPaper / addTrack / duplicatePaper`，挪音到另一行 = 1765 行附近），`src/score/clef.ts`（`startClef / pickClef / wantsGrand / resolveSongClefs`），`src/render/engrave.ts`（每张纸 `staves = p.staves === 2 ? 2 : 1`、`clefAtSys`、合租 `planHands` 的 `homes / force`），`src/format/project.ts`（`infoOf / clefInfo / autoOtt`、读回 `songFromReads`），`src/format/musicxml.ts`（`<staves>`、第一个 `<clef>` = info.clef、后面的 = 记号），`src/app/header-panel.ts`（`partHtml`）。
- 模型：`PartDef` 去掉 `clef / staves / autoOttava`（迁移后不再有）；`PaperSeg` 加一个可选记录「声部 id → { grand?: true; autoOttava?: false }」（名字施工时定，只存非默认）。手选单谱号 = 纸头的谱号记号（现成的）。
- `resolveSongClefs` 的结果从「谱号」变成「谱号 或 大谱表」，逐段带着上一段的结果当惯性；排版器每张纸 × 每个声部问它要行数。合租：`homes` = 每位在这一段解出来的开头谱号；`force` = 主人在这一段手选了大谱表。
- 自动变大谱表的数加线，照实际会画出来的样子数（上下行怎么分用 `staffOfTokens` 那一套），不要另写一套分法。
- 读：每张纸的 `<staves>2` 只管那一张纸。文件的 score minor < 3 = 老写法，走迁移（`src/format/migrate/` 里一条纯函数）：任何一张纸有 `<staves>2` → 整个声部每一段都是（老语义）；`parts[].clef` 是具体谱号 → 补纸头记号（在句号 / 音内起伏按编号挂回去**之后**补；编号反正在 `songFromReads` 里统一重编）；`parts[].autoOttava === false` → 每一段都关。minor ≥ 3 = 只认新位置，`parts[]` 里那两个旧字段不看。
- 写：`parts[].clef` 照旧每个声部都写 `"auto"`（不写的话旧版本会把第一份谱里的谱号当成声部默认）；`parts[].autoOttava` 不再写；`papers[i]` 加可选的 `autoOttava: { 声部 id: false }`。score minor 2 → 3。
- 别家的谱（没有我们的目录）：第一个不是普通高音谱号的 `<clef>` → 那张纸的纸头记号；`<staves>2` → 那张纸大谱表。
- 验收：
  1. 冻结样本里加一份老歌（声部默认低音谱号 + 一个大谱表声部 + 一个关了自动八度线的声部）：打开后每一行每个系统的谱号和迁移前逐个相同；存了再开还相同。
  2. 同一个声部 A 段高音、B 段大谱表、C 段低音：存了再开相同；整首的那份 MusicXML 里这个声部两行，A / C 的音都在第一行。
  3. 上面那张例子表逐条成立（单元测试）；外加「上一段大谱表 + 这一段在边上」接着用大谱表。
  4. 端到端：自动的一行里先写一串低音再写一串高音，行数变了不崩、光标还在原来那个音上。
  5. 面板：选什么显示什么；新段 / 放进一段 / 复制一段照「新东西从哪儿抄」那三条。

## 二、小调的歌从 la 数级数

user 11-09 夜：「同意，反正你需要选调号，就是在选调号的时候强制一起选。不过关系大小调对齐，免得没有乐理常识选错了，然后切换大小调会很方便」。

### 你会看到什么

谱头面板调号那里变成两行：

- **调号**下拉框：每一项把一对关系大小调并排写，比如「1=C · 6=A（没有升降号）」「1=G · 6=E（1 个升号）」。
- 紧跟一行两格的开关：「C 大调｜a 小调」，总有一格亮着，点一下就换。换调号时这个开关留在原来那一格（原来是小调，换到一个升号 = e 小调）。

切到小调之后：

- 这个声部从这个调号起，和弦级数从 la 数（a 小调里 Am = i、Dm = iv、E = V）。
- 调号上方多一行淡字「6=A」（原来 C 调时的淡字「1=C」同一个位置；有升降号的调也写，比如「6=E」），所以哪里是小调纸上一眼看得见。「按 C 调看」时写的「1=G」同样变成「6=E」。淡字和现在一样只在屏幕上，不印（「按 C 调看」那一行照现在的规矩印）。
- 音、升降号、音高、播放都不变。只影响级数怎么数。

范围：

- 调号现在的规矩是「只管这一个声部这一段」。大调 / 小调写在调号上，跟着调号走。
- 但在**这一段开头**切大小调时，这一段里调号相同的别的声部一起切，面板上写明碰了几个（「这一段调号一样的 3 个声部一起改了」）。理由：大调小调是这段音乐的事，不是某件乐器的事；一个个声部去点太费事。调号不一样的声部不动。
- 一段中间换调的那一处：只管这一个声部（别的声部在那个位置不一定有调号记号）。
- 新的一段、新放进来的声部：抄调号时大小调一起抄。移调 / 转调：大小调不变（a 小调移高一个全音 = b 小调）。

没做的：键盘上的「调式」那一列不跟这个开关（它管键盘怎么排，是另一件事）。

### 存进歌里什么

调号记号上多一个可选的小标记「小调」；没有 = 大调。写进谱里用的是 MusicXML 自带的写法（别的打谱软件认得）。大调的歌文件一个字节都不变。老歌读进来全是大调，和现在一样。旧版本打开新歌：照大调数；旧版本存一次，小调的标记会丢（音不丢）。

### 给施工的

- 落点：`KeyTok` 加 `mode?: "minor"`（`src/score/song.ts`）；凡是抄 `fifths` 的地方一起带（`headTokens / endMarks / setHeaderAt / addPaper / addTrack`、移调、剪贴板）；`src/format/musicxml.ts` 写 `<key><fifths>…</fifths><mode>minor</mode></key>`（只在小调时写 `<mode>`），读 `<mode>minor</mode>` = 小调、别的值 / 没有 = 大调。
- 理论：`src/theory/index.ts` 的 `BarNote` 加 `minor?: true`（来自它前面最近的调号记号）；`western.ts` 的 `readBar / brokenInBar` 把写死的 `MODE` 换成每个音自己带的；`Mode` 类型和 la 的测试留着。文件头「只看前面」③ 的退场条件到了：这就是「由人写明」。
- 淡字：`engrave.ts` 的 `keyHints` 现在只在专业模式 C 调出；改成「C 大调（现状）或 任何小调」都出，带上要写的字；`score-overlay.ts` 157 行写死的 `"1=C"` 改成用它。
- 界面字：关系小调的名字表放 `src/score/pitch.ts`（`KEY_LABEL` 旁边）；`marks.ts` 的记号名、记号编辑器的调号小格跟着写「6=A」。剪贴板的文字写法：小调写 `[6=A]`，读两种都认。
- 「这一段调号相同的声部一起切」做成 `song.ts` 里一个动词（一步撤销），面板只调它。
- 验收：大调歌存出来的每份谱和改之前逐字节相同；小调存了再开还是小调；a 小调里 Am / Dm / E 读成 i / iv / V；切大小调不动任何音；撤销一步回去；新段、新声部、复制、移调、app 内复制粘贴都带着大小调。

## 三、声部管理重做

user 11-09（截图）：「这里应该加delete的选项，记得护栏，然后parts也很乱，没法选其他的，然后delete也不对…parts应该比现状要compact很多，这样有十几个乐器一屏就能管理看完」「只是记账，你可以设计，opus执行」。

### 你会看到什么

一个声部一行（现在是三行），iPad 横屏一屏放得下 12 行以上：

```
● 笛子      竹笛 ›     [A][A2][B][C]   ⋯
● 埙        埙 ›       [A][  ][B][  ]   ⋯
  ● 鼓（挂在埙上）  鼓组 ›  [A][A2][B][C]   ⋯
● 钢琴      大钢琴 ›   [A][A2][B][C]   ⋯
                                  ＋ 新声部
```

- 色点 · **名字**（点一下才变成能改的框）· **乐器名**（点一下 = 换乐器，进乐器目录）· **段落小格**（亮 = 这一段有它；光标在的那一段小格带一圈）· 行尾 **⋯**。
- 段落小格：点暗的 = 放进那一段；点亮的 = 从那一段拿掉（那一段里它写了东西先问，写明几个音、能撤销；只有谱头的直接拿掉）。段多了小格那一块横着滑。
- **⋯** 里是对这一行做的事：上移 / 下移 / 在它上面新建声部… / 在它下面新建声部… / 「B」段交给…（光标在的那一段，名字写在钮上）/ 乐器设置… / **删掉声部…**（红）。
- 顶上那张钉死在「当前声部」的卡拿掉。打开时光标所在的那一行亮着并滚到看得见；想对哪一行做事就点哪一行的 ⋯。
- 挂在别人谱线上的声部缩进一格排在主人下面，挪动的规矩和现在一样（一家一起挪）。

删除两个词，分清楚：

- **从「B」段拿掉** = 只是那一段没有它，别的段照旧（点亮着的小格）。
- **删掉声部…** = 整个声部没了。不再要求「哪一段都不在了才能删」。确认框红色，写明：它在哪几段、各写了几个音；连同歌词、记号、它的乐器设置一起删；能撤销，一步全找回。哪一段都没写东西的 = 不问，直接删并说一句「撤销能找回来」。最后一个声部删不了（歌至少要有一个）。
- 歌手名旁边那张小卡（换乐器 / 乐器设置 / 声部管理）加第四颗「删掉声部…」（红），同一个确认框。混音台里的删除也走同一个。

要你拍的一处：删掉的声部如果是某一段**唯一**的声部（比如 B 段只有它）。见回复里的问题；设计稿按「确认框里写明，B 段一起删，一步撤销」写，你选另一条再改。

「从这一段拿掉」碰到那一段只有它：照现在，不拿，并说清楚出路（「B 段只有它。整段不要 = B 段的 ⋯ 里删这一段」）。

### 存进歌里什么

不动文件格式。删声部 = 一步撤销（谱和乐器设置一起回来），和现在「一段都不在时删掉」是同一条路，只是放开了条件、加了护栏。

### 给施工的

- 落点：`src/app/main.ts` 的 `openPartsManager`（整个重写；顶上的 `pm-here` 条和 `ctx` 那套拿掉，`give / add` 两个子页留着从 ⋯ 进）、`deleteSinger`（放开条件 + 确认框）、`dropFromSection`（不动）、`openTrackCard`（加第四颗）、混音台 glue 的 `deletePart`；`src/score/song.ts` 的 `removePart`（现在不防「删完某一段一个声部都不剩」——每张纸至少一行是全代码的前提，很多地方 `find(...)!`，这个前提不许破）。
- 整个删 = 一个纯函数算出「要删的声部 + 因此要一起删的段」，一次 `updateBoth` 提交；确认框的字从同一个结果里出（不许字和实际删的对不上）。
- 先查清再写确认框的字：删掉声部后它在混音台的那一条、它嵌在歌里的音色库现在各是什么下场（`withoutRole` + `pruneSounds` 管了哪些、没管哪些）；字照实写。查出没人管的东西 = 报给 Fable，不顺手改。
- 行高、小格大小以「iPad 横屏 12 个声部不用滚」为准；窄屏名字省略、小格横滑。别用按字长折行的按钮排。
- 验收（端到端）：12 个声部一屏；改名、换乐器、上下挪（含合租一家）、小格放进 / 拿掉（有音先问）、交给、在上 / 下新建；删一个在三段都有音的声部 → 确认框里的段名和音数对 → 删 → 一步撤销全回来（谱、歌词、乐器设置、混音台那一条）；最后一个声部删不了。

## 四、点开挑别的和弦读法

user 之前拍过「输入法候选」的做法：点开看到全部读法，挑一个。这一节定「挑中的怎么记」。

### 你会看到什么

- 点谱上的和弦级数，开出来的还是现在那张候选小表，只是每一行能点了：点哪个 = 用哪个，谱上的字马上换。
- 你挑过的那一处，级数旁边带一个小点，和自动认的分得开。再点开，顶上写「这是你挑的」，旁边一颗「改回自动」。
- 你挑的会一直留着，不会被别的操作悄悄删掉或换掉：
  - 后来把音改了，你挑的那个已经不在这几个音认得出的读法里 → 谱上照样写你挑的，但变灰；点开第一行告诉你「你挑的 Am7/C 不在现在这几个音的读法里」，你可以换一个或改回自动。app 不替你决定。
  - 音删了 = 挂在它身上的这一处跟着没（和歌词、演奏法一样；撤销一起回来）。
  - 复制、粘贴、复制一段：跟着音走。移调 / 转调：跟着音一起挪（Am7 移高一个全音 = Bm7）。只改调号：和弦名不变，级数照新调号重算。
- 挑读法是改歌，不是换个看法：以后有了修改锁，锁着时只能看候选、不能挑。
- 设置里「和弦标级数」关着时什么都不显示，挑过的也不显示（它们还在歌里）。

### 存进歌里什么

记的是和弦的本名，不是级数：根音（带升降）、和弦种类、最低音，挂在那个音上。写进这一段的谱里用的是 MusicXML 自带的「和弦记号」，所以给别的软件看的那份整首的谱里，你挑过的那几处会显示成和弦记号（Am7/C）。没挑过的地方什么都不写，歌文件不变。

旧版本打开：会说「丢掉了和弦记号」（它本来就这么对待和弦记号），照样能开；旧版本存一次，你挑的就没了（音不丢）。选这个写法而不是另开一张表，就是因为旧版本会明说，而且不会把你挑的挂到别的音上去。

这一版不接的：别人的谱子里带的和弦记号。它们常常标在两个音中间（一个长音底下换两次和弦），而我们这里的读法只能挂在音上；接一半会一片变灰。所以照旧：读进来时丢掉并告诉你。要接是另一件设计（「写在谱上方的和弦记号」），记在愿望单。

### 给施工的

- 落点：`src/app/main.ts` 的 `openChordInfo`（行变按钮）；`src/theory/index.ts`（`HarmonyRead` 加「是不是人挑的 / 挑的在不在候选里」；理论模块出「候选 → 存的那一条」「存的那一条 + 调 → 标签」两个纯函数）；`src/theory/western.ts`（`tpl` ↔ MusicXML `<kind>` 的对照表归它，`<kind text="m7">minor-seventh</kind>`；没有标准名的写 `other` + `text`；读到不认识的种类 = 只写和弦名、不写级数、灰）；`NoteTok` 加一个可选字段存这一条；`src/format/musicxml.ts` 写：紧挨在那个 `<note>` 前面一个 `<harmony>`；读：**只有我们自己的歌文件**（带 `.moonsinger/` 目录的）里、紧跟着一个音的 `<harmony>` 才挂上去，别的照旧 `drop`；`src/render/engrave.ts` 第 10 样挂件：挑过的音一定出标签（哪怕分解和弦重新分组后它不再是组头），带小点 / 变灰两种样子。
- 分解和弦「同一个和弦不重标」的那个 `prev`：挑过的标签也算进去。
- 移调的两个入口（整段 / 选区）一起挪根音和最低音，拼法用和音同一个函数。
- 不许做的：任何「音变了就自动清掉 / 自动换成最像的」。
- 验收：挑 → 存 → 开，还在；整首的 MusicXML 里有对应的 `<harmony>`；改一个音让它对不上 → 变灰、点开有那句话、没有被删；删音 → 没了、撤销回来；移调后名字跟着变、仍然对得上；别家的谱带和弦记号 → 和现在一样丢掉并报数；没挑过的歌存出来和改之前逐字节相同。

## 五、这一轮一共往歌文件里加什么

| 加的东西 | 写在哪 | 没有它 = | 旧版本存一次会怎样 |
|---|---|---|---|
| 某一段手选大谱表 | 那一段自己的谱（MusicXML 自带） | 一行 | 整个声部每一段都成大谱表 |
| 某一段关掉自动八度线 | 歌的附加信息里那一段的条目 | 开着 | 回到开着 |
| 调号上的「小调」 | 调号记号（MusicXML 自带） | 大调 | 回到大调 |
| 挑过的和弦读法 | 那个音前面的和弦记号（MusicXML 自带） | 自动认 | 没了，旧版本会说丢了和弦记号 |

- 附加信息（score）的小版本号 2 → 3：全是可选的东西，旧版本能开能改能存、提示一次。不用升大版本，老歌永远能开。
- 声部条目上的「默认谱号」「自动八度线」两个旧字段退役：读老歌时搬到每一段上（一条升级代码 + 冻结样本）；新歌里「默认谱号」照旧写「自动」给旧版本看。

顺手查出来的一个小口子（建议和第一件一起补）：旧一点的版本打开新歌时会说「那些东西保存时不会丢」，但对写在「某一段 / 某个声部条目里」的新东西，这句话不成立——那两张表是按歌重新生成的，不认识的键会掉（比如 v0.16.73 加的「分解和弦不认」，更旧的版本存一次就没了）。已经发出去的版本改不了；从这一版起，读的时候把这两张表每个条目里不认识的键按段 / 声部的 id 记住、写的时候放回去，这句话以后就是真的。

给以后加格式的人一条规矩（Fable 定，数据安全）：**按音的编号挂的东西，不许放进「不认识就原样带回」的地方。** 音的编号每次读都会重编，旧版本改过音之后再原样带回一张按编号挂的表，会挂到别的音上。这类东西要么挂在音自己身上（像这次的和弦记号），要么宁可让旧版本丢掉并明说。
